# F02：事实前提与解释假设分离（已批准方案）

日期：2026-10-20。状态：方案 A 已实施，离线验收完成；见[实施与验收记录](../reviews/2026-10-21-f02-implementation-validation.md)。

依据：[架构与工作流审查 F02](../reviews/2026-10-20-architecture-workflow-review.md)。
F01、F06 按用户说明已完成，本方案不重新设计这两项。
本方案以当前工作区（包括未提交改动）为基线，不启用整份 V8 远期规划。

## 问题与第一性原理

研究结论至少包含三个不同对象：

1. 观察：在特定来源、时点与口径下，已经取得什么信息。
2. 解释：这些观察可能意味着什么；解释仍可被反证。
3. 未知：哪些必要前提尚未取得或不能验证。

引用 ID 存在，只能证明“引用对象可找到”。数字来源正确，也不能证明
自由文字里的方向、因果或事实前提正确。给解释加“可能”，不能使其隐藏的
事实前提自动成立。

现有专项 `statement + supporting_fact_ids`、回应 `rationale`、综合理由均有
自由文字入口。因此只加强专项提示词，不能建立贯穿交付的保证。

## 方案比较

| 方案 | 可保证的范围 | 代价或局限 |
| --- | --- | --- |
| A：类型化观察、代码生成比较、解释分栏（推荐） | 引用身份、比较口径、数值方向、事实与假设的展示边界 | 需贯通 schema、工作流、持久化与 Reader；自由解释仍不是已证实事实 |
| B：增加模型逐句语义审查 | 可发现一部分隐含前提、错引和不当因果 | 增加调用与修复成本，仍可能漏检或误拒，不能替代确定性校验 |
| C：仅更新提示词和测试案例 | 成本低，可能改善模型服从度 | 没有新增发布约束，不足以修复 F02 |

推荐 A。不新增模型审查调用、不扩大取数范围。B 可在后续质量评测发现明确
剩余误差时另行决策。

## A 的具体行为

### 1. 观察由代码拥有，模型选择与组合

新增版本化的观察目录与前提绑定契约，复用现有冻结证据、数值目录及
结构化财务检查，避免另造一套财务计算语义。

- 来源观察：引用代码已经生成的 fact；展示保存原文及来源边界，不接受
  模型把另一句自由改写直接登记为“已验证事实”。
- 比较观察：引用可比较的两个合格锚点，由代码输出大于、小于、等于、
  正负状态及其明确口径。公司、字段、单位、币种、期间、累计/单期、
  合并/归母和供应商等必须满足对应计算契约。
- 有效证据不足、口径不兼容或来源冲突时，不能生成肯定观察。
- “亏损收窄”用负值大小关系表达，不能把负基数的普通增长率套用为改善；
  “现金流数值上升”也不自动等于“经营质量改善”。
- “主要贡献”“结构改善”“可持续”不属于简单大小比较，未有相应证明时
  留在解释或待验证问题中。

来源观察只保证忠实转述冻结材料，不保证供应商材料本身真实、完整。

### 2. 模型输出分成三部分

专项假设、回应与综合理由使用一致的语义结构：

- 已绑定观察：选择允许作用域内的观察 ID。
- 解释假设：解释这些观察的可能含义，保留反证条件。
- 待验证前提：明确缺什么，作为问题或条件，不作为已经发生的事实。

可成立的解释允许保留自然语言；不能将其整体标记为“事实已验证”。
自由文字的隐含前提不能仅靠新增字段或自报标签获得确定性证明。
这是方案的真实能力边界，需要在契约及验收中保留。

机器拒绝范围限于缺失契约、越界或失效引用、非法比较与绑定不一致。
“合法收入观察 + 无依据的费用断言”仍可能出现在自由解释中，必须单列语义
负向样本，记录人工判定与机器漏检，不宣称结构校验能拒绝任意混合句。
原混合句若不能按新契约形成有效绑定，应返回可定位的错误，进入现有有界
修复流程。修复失败时保留独立有效的观察和其他合格内容，拒绝该不合格
论证；禁止机械删去半句后把改变含义的残句当成原结论。

### 3. 江淮汽车实例

允许的交付表达：

> 已有观察：营业收入较上年同期增加；本期归母净利润为负。
>
> 解释假设：收入扩张尚未转化为盈利，原因仍需进一步识别。
>
> 待核实问题：销售费用是否增加，若增加，是否抵消部分规模收益？

没有销售费用的合格两期证据时，禁止登记或展示“销售费用增加”为已验证
观察，也不能用它作为已经成立的支撑。不会把“没有证据”解释成
“销售费用没有增加”。

### 4. 所有交付入口遵循相同边界

- 专项生成后校验；回应新增或修订的观察重新校验。
- 综合只能引用允许且仍有效的观察和假设；撤回、修订及未解决状态继续
  遵循现有支撑规则。
- 分段综合继续独立保留合格段；依赖失效前提的段不可发布为有效结论。
  总体与 critical 段失败仍走现有不评级规则，不另造评级降级政策。
- Reader 正文、专项展开、相关依据及 Markdown 使用同一保存契约，
  一致展示观察、解释、待验证前提。通俗解释也不得将待验证前提升级为事实。
- 如某个解释没有足够观察支撑，应呈现为待研究问题，不作为结论依据。

### 5. 版本与兼容

- 从 canonical Python schema 开始，再修改编译、校验、工作流和消费者。
- 使用独立策略版本进入新运行身份与缓存身份；旧运行保持原有读取、
  序列化和重放路径，不补写历史文件，不追认旧文本通过新检查。
- 新策略生成的内容缺少契约时不能静默退回旧自由文本路径。
- 不删除或迁移历史用户数据；不重启服务或自动发起真实模型运行。

## 验收

先固定证据做离线回归，不把测试通过等同于真实模型研究质量通过：

1. 江淮实例：收入、亏损保留；没有销售费用证据时，该变化不能进入已验证观察。
2. 越界或未知观察、非法比较在契约边界拒绝；部分句子有依据的自由文字另列语义评审与漏检。
3. 不同期次、单位、合并口径和冲突来源：不生成错误比较。
4. 零值、负基数、亏损收窄、现金净流出扩大：按明确算式生成准确观察。
5. 有界且诚实的解释、条件句和未知问题：不误拒，也不升级为已证实事实。
6. 回应和综合不能重新引入已被拒绝的观察；多个交付入口的标记一致。
7. 单条失效不抹掉其他有效材料；关键支撑失效不继续输出无依据评级。
8. 历史记录保持只读兼容；旧身份及重放不受新策略污染。

固定负向样本记录预期、实际结果、漏检和误拒。自由解释中的语义问题单列
人工评审结果，不能用“所有观察引用校验通过”代替“整句含义均获证明”。
真实模型对新契约的服从度、修复率、token 开销和结论质量另需获授权的运行。

## 已批准的取舍与后续

用户已确认采用 A：接受“观察更结构化、解释明确分层”的交付方式，换取
可复核的事实前提边界；同时接受自由解释的全面语义正确性仍需质量评审。

确认后先完成 F02 的实现与离线验收，再按审查顺序推进 F03 核查闭环、
F04 上下文、F05 检查点、F07 质量验收，最后处理批次模型的 runtime 归属。
后续涉及新的产品语义或不可逆迁移时再单独确认。
