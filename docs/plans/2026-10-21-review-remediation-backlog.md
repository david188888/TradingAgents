## 2. 目标、不变量与推进顺序

目标是让每个重要判断可以追溯到合格证据、让每个核查有明确用途和结果，
并在不损失必要信息及恢复可靠性的前提下降低运行成本。

- 交付完整性、事实支持、经济判断质量是不同维度，分别计量。
- 缺数据、未来才可观察、工具不支持和执行失败必须区分；零执行不自动等于错误。
- 压缩模型输入不得删除永久证据、改变数值精度、放宽引用作用域或隐藏反证。
- 新契约需要版本化；历史身份、记录、发布授权与只读 Reader 语义保持兼容。
- 保留全部现有未提交工作及用户数据；不隐含授权历史迁移、清理、服务重启或真实模型调用。

建议顺序：**先准备 F07 基线 → F03 → F04 → F05 → F07 总体验收**。
P3 可作为独立的小改动实施，但单独验收，避免与 F05 持久化格式变更混在一起。
这只是把质量标尺提前，主体整改顺序仍沿用原审查建议。

| 阶段 | 交付物 | 进入下一阶段的条件 |
| --- | --- | --- |
| 基线准备 | 固定样本清单、策略身份、证据哈希、评分草案及成本口径 | 人工评分者、重要性权重及对照方法确认 |
| F03 | 分类/原因契约、核查链路、结果投影、标注样本验收 | 每个重要挑战的去向可审计，覆盖率分母明确 |
| F04 | 各阶段证据视图、预算策略及固定输入对照 | 必需信息保留通过，成本与修复保障有测量证据 |
| F05 | 版本化对象/状态格式、恢复兼容及故障注入报告 | 写入放大降低，恢复与发布不变量通过 |
| F07 收尾 | 分项评分、失败样本、成本/质量对照及结论边界 | 按预先约定标准判断通过、未通过或无法判定 |
| P3 | runtime 模型归属、兼容入口及批次回归 | runtime 不依赖 Web 模型，保存格式及批次行为不变 |
