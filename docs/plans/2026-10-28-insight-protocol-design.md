# Insight 协议与研究判断边界

日期：2026-10-28。Status: Approved; implementation in progress detailed design。

依据：[已确认的迭代路线](2026-10-28-insight-first-research-roadmap.md)。本文细化第 1 项，尚不是已上线契约。
Do not use this document as evidence of current implementation behavior.

## 1. 已确认的职责变化

新研究使用独立版本的浅层协议；旧任务身份、旧记录读取和旧提示词保持兼容。
模型负责观点、语义判断、质疑和综合；程序负责来源保存、引用解析、数值计算、版本与发布完整性。
用户明确确认：综合 Agent 决定证据是否足以支持总体判断，程序不再因缺少旧规则指定的估值锚点而自动禁止“有利”。资料缺口必须明示，不能隐藏未完成的研究。

Pydantic 仍负责外部数据的边界校验。改变的是新契约的字段及职责，而非把旧契约中的错误数据强行放行。
不再把旧 Hypothesis/Challenge/Synthesis envelope 作为新产物的必经格式；内部复用来源、数值及执行基础设施，不继承旧分类与裁决门槛。

## 2. 专项 Agent 只输出四项

模型返回 `{"insights": [...]}`。每条 Insight 只有：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `claim` | string | 观点；明确是观察还是推断，不要求额外分类字段 |
| `evidence_refs` | string[] | 提供给该 Agent 的短引用编号；无证据可以为 `[]`，不得用 `null` |
| `reasoning` | string | 从依据到观点的推理；多项事实需就近引用 |
| `limitations` | string | 反证、替代解释、适用范围或信息局限；不要求必须找到反证 |

四项必需；正文不得为空。引用按首次出现顺序由程序去重，不因重复引用废弃观点。
不沿用“每条最多六个事实引用”和“正文最多四百字”作为研究准入条件；请求大小和生成长度受执行预算约束。引用数量上界自然受当前证据集合约束。
模型不输出 Insight ID、字段路径、观察下标、计算证明或发布状态。

下面所有公司、数字和材料均为合成设计样例，不是实际上市公司分析。

### 样例 A：有依据但不过度推断

程序提供的材料：`E1` 是公司甲某报告期的已保存收入数据及原始定位；`E2` 是已保存的该公司客户集中度披露片段。`N1` 是程序从 E1 读取、带公司/期间/单位的收入展示项。

```json
{
  "insights": [
    {
      "claim": "现有收入规模尚不足以证明客户结构具有韧性。",
      "evidence_refs": ["E1", "E2"],
      "reasoning": "已披露收入为 [N1]。公司同时披露客户集中度较高 [E2]，因此收入规模与单一客户依赖需要分开判断。",
      "limitations": "材料未覆盖后续订单变化，不能据此断言收入将下降。"
    }
  ]
}
```

程序将 `[N1]` 渲染为“公司甲／指定报告期／营业收入：10 亿元”等完整标签，保留来源入口；不是只替换成一个没有口径的裸数字。E1/E2/N1 都是短别名，内部映射由程序生成并随请求冻结保存。

### 样例 B：研究想法可以保留，但不能伪装成已获证据支持

```json
{
  "insights": [
    {
      "claim": "客户分散化可能改善收入稳定性。",
      "evidence_refs": [],
      "reasoning": "这是需要核查的研究假设，目前没有足够材料判断公司的客户结构是否发生变化。",
      "limitations": "需要客户结构和订单变化的后续披露。"
    }
  ]
}
```

程序保存为待验证；可作为研究问题展示，不能成为支持总体评级的已采纳依据。无证据不是整阶段崩溃的理由。

## 3. 引用与数字的最小规则

### 引用

`E1` 绑定到已保存来源的具体片段或结构化字段及其内容摘要、公司、时间和来源限制。来源 URL 只是访问入口，不能单独代替支持片段。
`[E1]` 可出现在正文中说明某句话的依据；程序合并正文引用、`evidence_refs` 及数字来源依赖，不要求模型同时维护两份完全一致的清单。
所有出现的引用都必须解析，不能静默丢掉坏引用后让原观点保持可采纳。无法解析时仅隔离该条 Insight。

编号映射冻结于该次请求及证据快照；重试、恢复及补证不得改变既有编号含义。最终跨阶段使用程序分配的 Insight ID，而非猜测另一阶段的 E1。
证据可来自对比公司或不同期间，但其主体和口径必须明确；不得把对比公司的数值自动当作研究公司的数值，也不靠“所有来源必须同一公司”屏蔽正常比较研究。

### 数字

优先使用已提供的 `[N1]` 指标引用：程序保留值、单位、期间、主体、原始输入和计算过程；模型只解释含义。
首轮先复用现有已计算指标及确定的计算能力，不让模型在 Insight 里编写算式或计算凭证。不支持的衍生指标写成待验证事项，不产生伪造数值；新计算类型另按实际研究需求扩展。

对模型自行书写的财务数值，不用“在材料里找到相同数字”作为验证。只有明确来源、指标、期间、单位及主体一致时才可确认；无法确认则该条进入待验证或一次修复，不让它支持结论。首个实现不做模糊数值自动匹配，修复提示要求换成提供的数字引用。
检测复用已验证的显式数量语法，并增加新协议的场景测试；年份、股票代码、列表序号不是金融量值，不能因为含有数字就拒绝整条。不能声称这种检测覆盖所有自然语言隐含数值或因果错误。

程序核验数值一致性，不把“数字正确”等同于“经济解释正确”。如模型用营收数值论证利润，语义错误必须在质疑、综合和内容评估中识别；不得宣传引用解析器已证明该推断正确。

## 4. 保存状态、失败隔离与修复

内部保存 ID、作者、原始提交序号、内容版本、证据快照、已解析引用、数值渲染依赖及安全诊断。它们不进入模型必填协议。

| 输入/事件 | 程序处理 | 对其他条目的影响 |
| --- | --- | --- |
| 结构完整且来源与数值链可核验 | 可采纳；不代表观点已被证明 | 无 |
| 没有支持证据、坏引用、无依据数值 | 待验证；显示具体缺口，不用于肯定支撑 | 合格条目继续保存 |
| 单条结构不可解析 | 记录条目序号和安全错误类别；不作为研究观点展示 | 合格兄弟条目保留 |
| 研究回应撤回观点 | 标为已排除，保留历史和撤回理由 | 仅失效相关依赖 |
| 研究回应修订观点 | 新版本重新核验；旧版本退出有效依据集合 | 未修订条目不重写 |
| 整体响应不是可解析 JSON | 阶段安全失败或一次有界修复，不猜测正文恢复结果 | 保留其他专项 |

每阶段最多一次仅针对失败条目的修复，计入既有总预算；无法解释为完成审阅的空输出保持真实状态。修复必须对应原条目，程序处理位置映射，模型不生成新身份。
外部数据在接入边界校验一次，内部用类型流转；恢复时对外部持久化数据验证完整性，发布时检查依赖有效性，不重复执行整套研究规则。

## 5. 一轮质疑与回应

质疑 Agent 接收已保存 Insight 及其来源上下文，返回针对具体 Insight 的“疑点/替代解释、引用、为什么影响判断”。目标以提供的短 Insight 编号选择；内部长 ID 由程序映射。
纯逻辑疑点可以无新增证据，但其中新增事实仍需引用。不给它风险等级、风险类型、condition_index、可验证性分类及工具需求组合表。

对已经阅读却未发现有效反证的观点，返回简短的审阅理由。程序区分“审阅完成且无有效反证”“尚未审阅”“审阅失败”。无有效反证无需编造引用或发起无意义回应。

有质疑时，所属专项进行一次回应，说明维持、修订或撤回及理由。修订用同一四项 Insight 内容，程序替换有效版本并保留历史。
无法回应不自动撤回观点，也不等于质疑已被解决：程序记录未解决状态，综合 Agent 必须看见它并作判断。
一轮是一次质疑阶段及最多一次各专项回应，不是无限循环；没有额外补证授权时只使用已保存资料。

示例：质疑“客户集中未必意味着订单不稳定，也可能来自长期合同”；回应“保留依赖风险判断，但撤回短期波动推断，因为没有合同期限证据”。最终报告应显示这一改变，而非仅显示挑战数为一。

## 6. 综合与发布

综合输入为持久化的有效 Insight、质疑与回应、研究缺口及其可追溯片段。未核验观点仅出现在待验证区，已撤回版本不能继续支持判断。
综合输出应保留以下信息：总体判断与可选立场、关键理由、局限和会改变判断的信息。理由引用 Insight，不另创一套路径与凭证。
综合可以形成新推断，但不能增加没有保存依据的新事实；如要使用新事实，必须先走证据与 Insight 保存流程，不能绕过边界。

用户已确认的评级规则：

1. 由综合 Agent 给出 `favorable`、`neutral`、`unfavorable` 或不评级；不评级必须有原因。
2. 不以缺少固定估值锚点、固定四维或机械挑战分类自动否决立场。
3. 程序要求立场有引用到有效 Insight 的理由；这只确认依据可追溯，语义是否充分由综合 Agent 负责并接受研究内容评估。
4. 资料缺口、审阅失败、尚未回应的质疑由程序保底展示，模型不能通过遗漏文字隐藏它们。
5. 总体判断本身的引用或数值校验失败时，修复或不发布该判断；保留独立合格观点，绝不自动替换为“中性”。

首轮优先保留总体判断为一个有依据的原子输出；其依据失效则整体不评级，不能在删掉理由后继续发布原评级。独立专项观点仍可交付。
缺少研究广度必须显示为部分覆盖，但部分覆盖不自动禁止由综合 Agent 明确给出的有边界判断。

## 7. 复用和迁移边界

保留：来源采集与保存、已实现数值计算、结构化输出客户端、执行预算、取消/恢复、持久化提交以及旧记录投影。
新建：Insight 提交与保存模型、简化引用解析与数值渲染、研究审阅记录、综合契约以及对应 Reader 投影。
只为新研究选择新版本；不批量改写旧用户数据，不把新产物伪装成旧 `research-record-v2`。可读取旧来源快照用于离线对照，但不能自动把旧失败结果认定为新协议已通过。

### 对已有失败的针对性验证

| 已观察到的问题 | 新设计要验证的变化 | 仍不能提前声称 |
| --- | --- | --- |
| `supporting_fact_ids` 字段校验失败 | 移除小数量上限，重复引用由程序去重，逐条隔离 | 原失败确实因数量或重复引起；当时诊断不足以证明 |
| challenge 分类/requirement 失败 | 新质疑不再携带这套分类和组合约束 | 无有效反证就是研究成功 |
| synthesis 动态 oneOf 本地构造失败 | 新契约不根据每次证据和维度生成大型动态分支 | 固定 schema 已完成真实模型验证 |
| 解释覆盖不完整 | 不再进入研究验收门槛 | 阅读辅助已经全部正常 |

## 8. 下一步实施与验收入口

先实现模型提交、宿主保存与逐条接纳的独立单元，再接入单个专项的保存及 Reader 链路。该链路跑通后扩展到其他专项、质疑回应和综合，不只交付一套没有接入运行入口的新 schema。

协议回归至少覆盖：有效样例、空引用、重复引用、未知引用、跨公司/跨期间数值误用、裸金融数字、正常年份和编号、坏兄弟条目、修复不改已接受条目、撤回失效、无反证与未审阅区别、综合坏引用及旧记录兼容。
离线测试验证确定性的程序行为；内容样例与获授权的真实研究验证观点质量和语义支持。两者都需要，不能互相替代。

白话解释覆盖率不参与验收。真实模型/搜索调用、预算扩张、服务重启及发布不因本设计通过而自动获得授权。

## Confirmed supplementary-search amendment (2026-10-29)

The user approved an independent outer `search_requests` list. Individual Insights retain their four fields.
The host assigns company, cutoff, deduplication and existing budgets; limitations are not implicit search instructions.
Initial specialist questions are processed in bounded batches; affected-role reanalysis is versioned.
