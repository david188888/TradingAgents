# DeepSeek effort 核查：按实际任务分配推理投入

Status: Historical

Do not use this document as evidence of current implementation behavior.
See the [documentation index](../../README.md).

这是 2026-10-04 对 `f18f7b1` 调用链的核查与候选策略，不是已实施的分阶段配置。
兼容修复位于独立工作树；当前配置行为见[运行说明](../../operations/llm-reasoning.md)。
用户要求先检查每个 agent/阶段可调整的 effort，再审阅具体分工；没有授权付费对照。

## 核查结论

优先研究辅助调用的降档：新闻语义聚类、单条新闻分类、已有公开内容的压缩。
经营分析、事件兑现、反证和最终综合先保留 `high`；`max` 只作为复杂问题的专项
对照候选。原生 `market_context` 是首个可评估 `high → low` 的专项，但不能据此直接降档。
最终简报的精简由输出结构、数量限制和确定性渲染控制，不靠减少思考投入。

官方实际档位为 `low / high / max`，默认 `high`；`medium / xhigh` 实际都是 `high`。
这是同一模型的投入差异，不能当作独立模型验证。
依据：[官方思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 第一性原理：决定档位的四个问题

1. 输出是复制/分类已有材料，还是判断机制、替代解释和失效条件？后者需要更多推理。
2. 能否用代码或现成模板完成？能则不新增模型调用；不存在所谓代码阶段的 effort。
3. 错误会不会改变证据资格、遗漏重大风险或影响最终判断？会则不能只凭结构通过降档。
4. 降档是否增加修复、重跑或后续误判？成本要计入思考 token、修复、耗时与截断，
   不能只计最终字数。高档位也不补足缺失正文、时间戳或经营数据。

以下建议来自任务结构，**尚无付费效果测量**。代码验证能检查格式/引用，但不能证明
经济推断成立；不同角色共享模型盲点，隔离上下文与工具核查仍各自必要。

## evidence_v1：实际五个模型阶段

入口为 [NativeModelCaller](../../../tradingagents/execution/native_model.py)，
流程由 [native_research.py](../../../tradingagents/graph/native_research.py) 固定组织。
当前全部读取同一全局 effort；只有 synthesis 选择 deep 模型，其余选择 quick 模型。

| 阶段 | 当前任务 | 候选 effort | 调整边界与验收重点 |
| --- | --- | --- | --- |
| `operating_quality` 经营分析 | 从经营事实提出可证伪假设、必要/失效条件与替代解释 | `high`；复杂披露可对照 `max` | 收入、利润、现金流与期间口径的联系可能决定结论，不宜先降档。检查是否把相关性说成兑现。 |
| `event_context` 事件分析 | 判断公告证据能支持什么假设与兑现条件 | `high` | 标题不证明签约、生效、交付或收益兑现。单纯时间线摘录可用 low，但当前阶段还承担机制分析，不能整段当摘录。 |
| `market_context` 市场背景 | 在限定行情事实和代码计算指标上提出假设与条件 | 首个 `low` 对照候选；当前先保留 `high` | 输入较窄且指标已算好，推理负担可能较低。检查是否越界推断估值、因果或未来价格，是否保留复权/覆盖限制。 |
| `challenge` 反证 | 指出替代解释、缺失证据及失效条件，选择已有条件进行核查 | `high`；强冲突可对照 `max` | 漏掉关键反证可造成错误自信；增加档位不代表反证独立。没有假设时当前代码跳过该调用。 |
| `synthesis` 最终综合 | 按维度结合支持、挑战、核查和限制形成简报 | `high`；多重关键冲突可对照 `max` | 检查是否把数值条件通过当成经济假设成立、是否遗漏关键挑战。不能因输出短而把它归为简单摘要。 |

无合格专项事实时当前代码跳过对应专项。采集、PDF/表格提取、证据准入、指标计算、
C1 确定性核查、资格校验与 Reader/Markdown 渲染不需要模型 effort。

**结构修复不是纯格式转换。** `_repair()` 带原证据和 schema 重新生成完整提议，
没有把上次无效对象交给它做最小修改。因此先继承原阶段 effort；不能凭“repair”名称
将其设为 low，更不能额外增加一次未计费重试或在恢复时重新生成已派发阶段。

## classic：默认路径的主要 agent

[GraphSetup](../../../tradingagents/graph/setup.py) 将四个分析师及多空研究者连接到 quick
客户端，Research Manager 使用 deep 客户端；两个客户端仍用同一全局 effort。
“quick”不是低档位，“deep”也不是另一种 effort。

| Agent/任务 | 建议 | 原因 |
| --- | --- | --- |
| 基本面分析师 | `high` | 财报关系、经营机制、时间口径和必要数据缺失解释。当前不是简单表格摘录。 |
| 市场分析师 | `high`；可在约束输出后对照 `low` | 同时处理调整价格、资金流和风险背景，且含工具选择与解释。数值计算本身由代码做。 |
| 新闻分析师 | `high` | 公司证据与宏观背景取舍、事件意义、资料范围和覆盖限制。纯事件清单可考虑 low，但当前 prompt 要求影响解释。 |
| A 股情绪分析师 | 次级 `low` 对照候选；当前先保留 `high` | 预取输入较明确，但还要解释资金/融资/内部人信号冲突与脆弱性。不能把预取或结构化输出误称为没有推理。 |
| Bull/Bear Researcher | `high` | 论点、传导链、替代解释与相互反驳；同模型双方同意不证明事实独立。 |
| Research Manager | `high`；复杂冲突可对照 `max` | 产出事实、推论、未知、情景、失效条件及持仓假设评估。较小的 summary fallback 仍是综合任务。 |
| Portfolio Manager | 无 effort | 当前公开学习研究路径是确定性收尾，虽然工厂形参叫 llm，实际不调用模型。 |
| Evidence Steward 的资格规则 | 无 effort；附属模型见下表 | 公司身份、资格与阈值由代码处理，但它调用的数据层包含模型辅助任务，不能说整个节点无模型。 |

classic 的 analyst 工具循环、结构化回退、经理纠错可能产生额外模型调用，不能按
“一个 agent 等于一次调用”估算费用。降低整个 quick 客户端会同时降低多空研究者，
因此不推荐直接设置“quick=low、deep=high”作为完整分工方案。

## 容易漏掉的辅助模型调用

| 调用位置 | 什么时候执行/当前设置 | 候选与风险 |
| --- | --- | --- |
| [新闻语义聚类](../../../tradingagents/dataflows/consistency.py) | consistency 默认开启；有模型且多于一条新闻时可调用。curator 在多源成功时使用，Evidence Steward 评估原始/补充新闻也使用；读取全局 effort | `low` 候选。必须检查不同公司、不同报告期、意向与履行被误合并；聚类影响 cross_source 权重，不是无风险去重。 |
| [新闻覆盖顾问](../../../tradingagents/dataflows/news_advisor.py) | news_advisor 默认开启；Evidence Steward 初始资格不足且未硬停时识别缺口并生成最多三条查询；读取全局 effort | `low` 对照候选。检查关键公告/财务缺口遗漏、无必要搜索；涉及关键资料取舍时不宜直接降档。 |
| 单条新闻 Layer 1 分类 | 默认关闭；显式开启后一次紧凑批量分类，仍用传入的全局客户端 | 较适合 `low`。只做方向分类，保留“不足以判断”，校验 ID、遗漏和否定语义；不要为了测试降档而启用当前关闭的调用。 |
| 新闻 Layer 2 复查 | 默认关闭；启用后按冲突/不足触发，且需要缓存目录；仍用同一客户端 | `high`。它整理重大风险与证据缺口，名称中的“deeper”目前没有自动提高 effort。 |
| [辩论上下文压缩](../../../tradingagents/graph/setup.py) | 超过上下文限制或溢出时摘要早期公开主张，使用 quick 客户端；有代码提取回退 | `low` 候选。保留原文出处、否定、分歧、未解决风险；不能将压缩变成第二次裁决。需比较代码提取是否已足够。 |
| [classic 完成后辩论索引](../../../tradingagents/web/debate_summary.py) | 完成后后台生成，缺缓存的 classic 读取也可生成；仅传 provider/model，**未传全局 effort**，官方当前默认 high | `low` 候选，失败不改原运行结果。摘要仍可能误导阅读，要保留争议及原记录入口。native/catalyst 跳过后台调度；通用视图缓存仍可进入 helper，但无辩论轮次时不调用模型。不能为 native Reader 新增此调用。 |

这里的默认来自仓库配置，不代表用户本地覆盖值；本轮未读取密钥、用户预设或历史报告。

## 三种可选实施方法

1. **按真实调用任务固定分工（推荐）**：核心分析保持 high；先在已有辅助任务上
   对照 low，再考虑 market_context。需要覆盖 graph、数据层及完成后索引的实际入口，
   不增加模型阶段。分工经确认后才增加少量明确配置。
2. **只按 quick/deep 分工**：改动少，但四分析师、多空研究者、聚类等共享 quick；
   无法把简单分类和关键反证区别对待，不满足当前准确性目标。
3. **自动按难度升降档**：需定义难度与升级依据、计费和恢复规则；目前没有经过验证的
   难度判据，也不能把结构成功当语义正确。因此暂不实施自动 low→high→max 重跑。

推荐先检查固定分工。`max` 不作为默认，也不在数据失败时自动补用；缺资料应保留未知。
若未来增加 per-role/stage 配置，需要校验真实档位、构造独立参数，保存解析后的策略
与语义指纹。恢复沿用已保存策略；不能原地改共享客户端参数，避免并行专项互相污染。
旧配置无新策略键时仍使用原全局值，不重写已保存记录或把旧调用重新派发。

## 尚需验证的质量与费用

优先对照顺序：已有内容压缩、紧凑分类、覆盖查询/聚类，随后市场背景专项。
使用相同已保存输入，固定输出 schema、提示与预算，分别对照 low/high。
检查公司/期间混淆、意向与兑现混淆、否定语义、错误交叉确认、重大风险遗漏、
引用越界、空内容/截断、实际 token 和修复次数。推理 token 与最终字数分开计量。

代码级参数和恢复测试不证明投资判断质量。真实模型对照还需用户确认费用上限和
案例；本轮不进行付费调用，也不新增自动策略。
