# 研究流程总览与相邻详情设计

- **Status: Frozen Design** — Do not use this document as evidence of current implementation behavior.

日期：2026-10-11。用户已确认 A 布局与 C 视觉组合，并确认本文继续实施；设计审查已通过。当前实现参见 [Reader 架构](../../architecture/research-reader.md)。

## 目标与边界

研究页面应让用户快速知道：当前执行到哪里、各专项接收什么输入、保存了什么、为何能继续或停止。采用 A 的依赖流程和相邻详情，吸收 C 的淡点阵背景、清楚的节点边界与连接线；默认保持适配容器的布局，不引入缩放、拖拽或无限画布。

本次改造覆盖未发布原生研究页面、已发布报告中的“研究过程”和共用 Agent 详情样式/状态文案。报告结论、证据目录和完整记录保留现有内容与导航。诊断已完成，本设计不改变核查规则、模型修复策略、预算、用户记录或历史恢复行为，不自动创建新的付费研究。

600418 最新失败依据：`docs/reviews/2026-10-11-600418-latest-failure.md`。当前错误分类 `missing_configuration` 已确认有误，核心异常分类与前置语义校验修复作为另一个独立修复建议处理；本次 UI 不伪造新的错误类型或把运行失败推断成数据缺失。

## 结构与依赖

桌面在现有阅读容器中呈现流程面板和相邻详情，比例约 2:1，主图有清楚的输入/分工/汇合分组；窄容器将详情置于流程下方。断点按实际可用容器宽度决定，流程在不足以承载三列时纵向显示专项，并保留“独立专项分工”组名，避免误示为串行。

现役 V7 顺序：证据冻结 → 独立专项（经营、事件、市场）→ 汇合 → 独立挑战 → 代码条件核查 → 有目标的专项回应 → 综合 → 发布。流程图表示资料依赖，运行状态来自持久 DTO/SSE；不得把绘制的依赖图当作确证实际并发执行。代码条件核查与发布在现有 DTO 中是组合角色，因此以同一代码角色的两个依赖位置作说明，而非制造两个执行实例、重复统计或凭空分配进度。两个位置使用不同展示 ID、共享 `code_checks` role key 与详情选择，统计只展示一次；其 `not_applicable` 状态不能推导具体执行进度。

角色集合优先读取合格过程 DTO；读取期间使用已有版本化注册表回退。`rolesForProfile` 不包含代码角色，流程说明需显式保留对应代码位置；未知版本使用兼容提示与已有角色状态列表，不擅自套用 V7 图。

历史 V1–V6 依据代码已有的版本/角色集合显示其原有流程，不展示不存在的专项回应。关注点回应仅在已请求且版本支持时显示于已保存基础研究之后；不成为综合输入。

每个角色节点显示名称、角色执行状态、公开产物状态及查看入口。数量只在现有合格 API 提供 `output_count` 时显示；对保存但未发布提议，若 API 未提供数量则不读取 checkpoint 或显示推测数值。总来源/事实/指标数只从可用公开记录读取；失败案例预览中的调查数字不能变成生产 UI 的常量。

## 展示状态

执行和产物状态独立：`completed` 表示角色执行结束；`available` 表示产物可回顾；`pending_publication` 表示存在已保存提议但正文尚未发布。终止且未发布时显示“提议已保存 · 本次未发布”，不继续称“等待发布”。未到达角色显示“后续未执行”，跳过/无目标回应显示真实原因；代码角色 `not_applicable` 保留其代码职责说明，不误标执行失败。

顶栏区分执行中、取消中、失败、已取消、已中断、已完成。API 确认没有发布记录时明确提示“本次未生成可读最终报告”；仍在读取时显示“正在核对保存记录”，读取失败时显示可重试的读取错误，不将后两者当成确定未发布。已发布但角色产物读取失败时保留已发布报告入口。只在 API 提供具体阶段诊断时标注该阶段失败；三个专项已 completed 而全局失败时，显示“运行已停止”，不能凭角色顺序或缺失产物认定某个节点失败。

过程读取失败显示可重试状态；角色读取失败单独显示重试入口；未知/unsupported 历史版本提供明确兼容提示。维持 run ID、sequence 和 hook 的旧响应防护。新建/重试/恢复/取消仍用原有回调和资格规则，不增添自动执行。

共用 Agent 详情删除对所有不可用产物统一追加“最终报告仍可阅读”的做法：有合格已发布记录时才显示此提示。无发布记录时只说明保存状态、读取资格及本次运行结果。

## 交互与视觉

页面为浅色研究工作台，淡点阵限定在流程背景，避免影响正文阅读。节点有清楚的边界、留白和状态徽标；选中用边框和底色，运行用适度高亮，失败用静态警示。连接线表达分发/汇合和前后依赖，未到达路径使用虚线。使用中文短标签解释关系，不只靠颜色或箭头。

节点选择后，就近详情显示“输入范围 → 保存产物/读取状态 → 下游关系”；技术统计和记录口径默认折叠。公开正文仅由 `useReaderAgent` 读取并按既有资格展示，不暴露提示词、模型响应或内部思考。已有事实/来源链接及最终记录定位仍由 NativeReader 回调处理。

所有节点为原生 button；保持 `aria-expanded`、详情 `aria-controls` 和明确名称。选择后详情进入视野并获得焦点；再次点击相同节点仍能定位，关闭后返回触发节点。相邻详情不要求桌面滚动到列表底部。狭窄容器只滚动选中详情，无横向拖动要求；重试不丢失选择，切换运行清除旧运行选中状态和详情。

动效仅用于真实 `running` 状态的节点及其活动连接，采用轻微流动/脉冲；不显示伪进度或计时。完成、失败、取消、中断、等待状态静止。`prefers-reduced-motion: reduce` 关闭动画和非必要过渡；键盘和触屏无需悬停才能使用入口。

## 代码职责

- `NativeResearchPage.tsx` 保留状态/操作组合，调用共用流程与详情组件，不引入叶组件自行取数。
- `NativeReader.tsx` 的过程视图复用同一流程组件，接入已发布记录、现有角色查看与定位能力。
- 独立流程组件负责版本化分组、依赖连接和选择；输入为现有角色 DTO、运行状态及回调，不获取网络或构造研究正文。
- `ReaderAgentOutput.tsx` 保持产物渲染职责，接收真实发布/终止上下文以生成准确状态说明。
- `nativeReader.css` 为未发布页面和已发布 Reader 提供一致 tokens、按钮、正文层次、容器适配与动态偏好，不依赖只有 `.question-reader` 祖先时才生效的隐式规则。
- 现有 API、closed DTO、预算与持久存储契约不变；生成资源与 frontend 源码一起更新。

## 验收

1. 真实失败运行显示已停止、报告未发布，三个专项仍保留真实执行结束状态，后续未执行；不显示“最终报告可读”，不伪造失败节点或数量。
2. 运行中、取消中、完成、失败、取消、中断、无目标跳过、过程读取失败、记录读取中/失败、角色读取失败、历史不支持状态均有准确可操作展示；已发布报告中的 Agent 回顾仍可用。明确覆盖 V6 含 focus、V7 无目标回应和未知版本。
3. 鼠标/键盘打开、重复点击、角色切换、关闭返回焦点、重试读取与运行切换均通过；详情接口遵循原有 hook 数据边界。
4. 在窄工作台容器、390px 移动端及 1366px 桌面验证关系可读且无水平溢出；减少动态效果偏好下无运行动画。失败/停止时连接静止。
5. 使用现有 Vitest 与 Playwright 测试维护相关行为；测试关注状态真实性、依赖分组及交互结果。执行 agent-doc check、适用 Ruff、npm ci/typecheck/build/Vitest/相关 E2E、diff check；保存可核对的浏览器截图，生成 SPA 资源一起交付。

实现前以本文件确认范围；核心提议绑定修复、错误分类修复及真实模型复跑不隐含在 UI 设计确认中。
