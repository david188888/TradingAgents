冻结时的基线与拟议设计保留作历史，实际交付见[收尾记录](../../reviews/2026-10-24-dual-search-closeout.md)及[现役合同](../../contracts/dual-search-research.md)。

## 1. 用户已确认的目标与约束

专用接口优先提供公司身份、简介、主营业务及财报、行情、估值等量化数据。
新闻、行业、竞争、政策及事件背景从开始就主要通过 DeepSeek 和 Tavily 双路检索。
专用接口耗尽可用候选后，或某项必需字段不足时，搜索也用于补齐该项数据；不是只提供旁注。
研究 Agent 可以在分析期间提出明确的证据缺口，触发有上限的补搜并更新分析。

每家公司、每次独立研究共同使用以下额度；批量研究的每个子 run 单独计账：

| 预算 | 上限 | 消耗口径 |
| --- | --- | --- |
| DeepSeek Search | 50 次 | 初始、数据回退、研究补搜及所有重试的已派发请求 |
| Tavily Search | 50 次 | 同上，不按 Agent、密钥或阶段重置 |
| 额外正文获取 | 8 次 URL 尝试 | DeepSeek Fetch、Tavily Extract 或搜索发现 URL 的直接获取共同计数 |
| 研究中补搜 | 3 轮 | 全部 Agent 共用，一轮处理一批优先缺口 |
| 搜索活动时间 | 90 秒 | 检索、正文获取及该批次处理的累计活动墙钟时间 |
| 补证复核模型尝试 | 9 次 | 每轮最多 3 次实际尝试，包含失败、重试及修复 |
| 基础流程模型尝试 | 12 次 | 沿用基础分析、综合、可选 focus、网络重试及修复的总池 |
| 全部模型尝试 | 21 次 | 基础 12 与复核 9 的共同父上限 |

上限不是使用目标；足够回答问题就停止。每轮每个相关专项最多一个逻辑复核任务；
同任务的重试占用本轮三个实际尝试之一，因此重试可能导致其他专项未获复核机会。
第三轮结束后不再生成可执行补搜，只记录剩余问题。
此次不延长整次研究的默认 300 秒活动时限；更早到达任一相关时限即停止对应工作。

## 2. 设计冻结时的 V7 基线与外部契约核对

2026-10-23 阅读代码所得的设计约束：

- `execution/native_runner.py` 当前为新 V7 选择 `MinimumEvidenceSources`，不经过旧 Tavily 新闻路由。
- `dataflows/native_sources.py` 和 `minimum_sources.py` 负责定向接口、公告正文和量化数据采集。
- `research/native_policy.py` 的专项事实视图依赖有限来源族；仅增加搜索供应商不会自动让新材料进入专项。
- `execution/budget.py` 默认有 24 次数据能力调用、64 次数据 HTTP 尝试；新搜索不能与旧额度混用后提前被截断。
- `ResearchRecordV1` 的快照仅允许 V0／V1；验证器和 `verification_executor.py` 也绑定这一转换。
  三轮追加证据不能通过直接放宽某个列表长度完成。
- 当前 V7 的基础主要模型调用上限是 8 次，全部尝试为 12 次；新复核使用独立子预算。

官方契约核对来源：

- [DeepSeek Search／Fetch 指南](https://api-docs.deepseek.com/zh-cn/guides/search/)：独立 JSON 接口；Search 的查询长限、日期和站点语法、可选正文，以及 Fetch 的 Markdown 返回。
- [DeepSeek Search](https://api-docs.deepseek.com/zh-cn/api/search/)／[Fetch](https://api-docs.deepseek.com/zh-cn/api/fetch/)：实现前以请求及响应 schema 校验适配器。
- [Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search)／[Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract)：搜索及正文获取分开；批量提取须同时检查成功和失败列表。
- [Tavily 计费](https://docs.tavily.com/documentation/api-credits)：搜索深度和成功提取页数会影响 credit，不能以 HTTP 次数替代费用。

文档没有证明哪一家在 A 股中文资料上覆盖更好，不据此固定语言或地域分工。

## 3. 方案选择及责任边界

采用“类型路由＋独立检索服务＋追加证据版本”的方案。
只给旧新闻路由增加 DeepSeek，不能覆盖当前主流程；让每个 Agent 自行无限调用工具，
也无法统一预算、去重和恢复。两者均不作为本次实现路线。

| 单元 | 输入与输出 | 所属责任 |
| --- | --- | --- |
| 信息需求路由 | 类型明确的资料需求 → 专用接口或检索任务 | `dataflows/`；不做研究评级 |
| 两家服务适配器 | 查询或 URL → 保留原始字段的规范结果、明确失败状态 | `dataflows/`；无隐藏重试、无模型调用 |
| 检索协调器 | 缺口、已用额度 → 双路任务、去重材料、停止原因 | `execution/`；所有外部 I/O 的调度入口 |
| 证据准入与字段校验 | 原文／字段 → 可引用观察、可计算字段或未核实材料 | `research/` 的纯规则及解析；模型仅提议 |
| 研究控制器 | 分阶段产物、证据版本 → 最多三轮请求与相关专项复核 | `execution/` 调度，`graph/` 保持注入式依赖 |
| 研究记录与投影 | 已保存记录 → Reader、过程详情、Markdown | `runtime/` 持久化，Web／前端只读展示 |

内核不导入 HTTP SDK。通过执行层注入的有预算检索入口获取补证结果，
不能从角色提示词或工具封装绕过执行层。配置和凭证与研究模型供应商独立，
使用 ChatGPT 等模型时仍可调用这两个检索服务。

## 4. 信息路由与初始采集

1. 按已有候选接口取得身份、简介和量化数据；按能力记录成功、缺字段或失败。
2. 新闻、行业与竞争三个基础主题分别在两家服务检索，通常为六个初始请求；
   问题模板由已核实公司身份、截止日期和研究目标构造，不增加专门规划模型调用。
3. 接口未满足的能力进入数据回退队列。身份缺失先核对股票代码、交易所和公司名称，
   未取得唯一身份时不得把疑似同名公司材料送入正式分析。
4. 两路材料统一规范化、去重、校验，再形成初始证据版本及专项视图。

这些是确定的初始任务，不要求耗尽额度。默认全网发现，不套用原接口网站白名单；
针对特定数值或文件时可以限定发行人、交易所、监管机构等站点。
已有可用正文直接复用，不为同一页重复付费抓取。Search 同次返回的正文不额外计 URL 获取，
但仍执行正文长度和相关性限制。

专用接口单次传输失败先遵循原有限候选策略；不在每个失败请求后重复开启一套搜索。
字段不足也能触发回退，而不要求整个接口完全失败。取消、全局期限、预算拒绝、
持久化冲突、安全策略拒绝或疑似凭证泄露不能伪装为资料不足后继续调用。
普通供应商 401／402 是对应服务不可用；停止该服务的原样重试后，可以按额度使用其他服务回退。

## 5. 研究中三轮补搜与复核

初始专项、质疑及原有专项回应仍按既有职责执行；新版提议契约允许在相应产物中
附带结构化缺口，不再把自由文本 unknowns 直接当搜索指令。
在最终综合之前处理这些请求，最多三轮。每轮完成后的复核可以提出下一轮缺口。

一个缺口说明：要回答的问题、对应假设／挑战或缺失能力、为什么影响判断、
需要何种证据、截止时间，以及哪些结果可能支持或反驳当前解释。
不要求 Agent 给出搜索 API 参数或执行计划；查询编译和执行由宿主负责。

每轮执行顺序：

1. 合并同问题、同目标字段和同时间范围的请求，优先处理影响判断的 critical／material 缺口。
   每轮最多选三个缺口；其余保留排队，最终显式记录未执行原因。
2. 每个缺口每家最多编译两个有区别的查询；两家均可用且有额度时双路搜索。
   查询覆盖核实与反证，不仅检索模型原结论的同义表达。
3. 对候选做出处追踪、正文取得、时间／身份检查及去重，形成追加材料。
4. 有合格增量时追加一个不可变证据版本，重算受影响的确定性字段和检查。
   只向相关专项提供它可以使用的新事实及自身原判断，不泄露其他专项草稿。
5. 每个相关专项最多发起一个逻辑复核任务；各轮实际模型尝试合计最多三次，
   按缺口优先级及固定角色顺序分配。无关专项不调用；失败不被描述为已经更新。
6. 保存维持、修正、撤回或无法判断的处置及引用，也保存新风险和下一轮缺口。
   同一问题在同一证据版本不重复检索；一整轮没有相关合格增量则提前结束。

最终综合一次读取最新事实、原始假设／条件、挑战、版本化检查和各专项最近可用复核。
补证复核不能重写原假设条件或删除挑战；新发现的风险进入未解决事项。
被撤回或修正的旧推断不能继续作为肯定性支撑。未完成复核的关键冲突保持未解决，
不得仅因获得新材料就自动提高判断强度。

初始采集和接口数据回退不占三轮研究补搜，但它们消耗相同的服务次数、正文和时间预算。
最终综合、可选 focus 和 Reader 不能再触发第四轮或隐藏搜索。

## 6. 搜索结果如何补回可用数据

搜索摘要、网页原文、第三方观点和已核对字段分别保存；相关性、authority／score
只是供应商元数据，不是本系统置信度，也不能直接跨服务比较。

- 观察类事实必须能追溯到保存的原文片段、URL、发布者和可核实时间；明确“公司称”“媒体报道”“机构预测”。
- 用于计算的字段必须核对证券身份、指标定义、报告期／交易日、单位、币种、口径和原文位置，
  通过确定性的解析与校验才成为可计算输入；保留网页来源及提取血缘，不能冒名为新浪／Tushare。
- 搜索发现的年报或数据文件可以使用已有本地解析器。符合相同字段需求的材料可以补齐对应能力，
  进而重算财务比较、估值或价格统计；不以“不在旧来源列表”为由拒绝合格输入。
- 无可用解析器、口径不清或字段不足时，保留材料但不宣称数据已补齐；首版不增加付费 OCR／提取模型。
- 搜到一个收入数字不能补齐整张三表；收益率报道不能代替逐日复权行情；机构预测不能当成实际利润。
  恢复程度按字段、期间和窗口逐项记录。

未知日期不猜测为当天。历史研究不能仅凭搜索日期或当前页面取得时间证明截止时已可知；
历史版本无法核实时保持未核实。检索时间、发布时间、事件时间分别保存。
同一网页经两家搜到，以及同一公告被多站转载，不增加独立信源数。
来源冲突保留两边、注明差异，不以搜索排名或多数转载自动裁定。
网页中的指令只作为不可信文本，不能改变研究任务、工具调用或预算。

## 7. 预算、计时、错误和费用

使用一个持久化账本。调用前原子预留，派发即占用；结果未知也占用，未派发的释放。
阶段、Agent、服务密钥和断点恢复都不能创建新配额。已有结果按身份哈希复用，不重复付费。

旧专用接口保留 24 次能力／64 次 HTTP 的子池；搜索不消耗这两个子池。
新工作流另外计两个 Search 子池和正文 URL 子池，所有 HTTP 派发再汇总到最多 172 次
（64＋50＋50＋8）的父上限，不允许通过换传输或内部重试突破。
第一版正文提取按一个 URL 一次外部调用执行，避免批量接口把八页上限放大；
直接下载的重定向逐次计 URL／HTTP 尝试，最多跟随两跳，并受同一八次额度限制。
搜索发现的下载地址及每跳目标须为无凭证的公开 HTTP／HTTPS URL，解析后的目标不能是
回环、私网、链路本地或云元数据地址；每跳重新校验，保留既有解析器的字节／页数上限。

基础模型 12、复核模型 9、全部模型 21 分别受限；复核的网络重试及格式修复也属于复核池，
不借用基础 12。沿用原有修复／网络重试子上限作为额外约束，不把它们额外相加到 21。
不增加独立模型来规划查询、判断是否继续或解释预算耗尽；这些由既有产物和宿主规则完成。
开始复核前优先保留尚未派发的综合、可选 focus 的基础额度；时间不足时仍可无法完成，
不能保证运行会用满 21 次或一定形成评级。

90 秒按搜索相关批次活动区间的并集累积：两家并发只算一次墙钟，
批次包括排队、退避、检索、正文和相关解析，不包括研究模型推理及用户等待。
单请求超时取服务超时、剩余搜索时间、整次研究剩余时间三者最小值。
累计耗时持久化；崩溃遗留的未结算批次按派发时已保留的批次截止额度保守计入，
不以进程重启或更换模型重置时钟。

凭证缺失、鉴权失败、余额不足、暂时限流、超时、空结果、正文失败、时间无法核实、
字段未合格、重复材料、无增量、预算拒绝和取消分别记录。两家之一不可用时允许另一家
在自己的剩余额度内工作，并展示双路覆盖降级。均不可用时交付已有合格材料及明确缺口。
必需身份等仍不合格时沿用显式拒绝／部分交付语义，不生成伪造基础事实。

每个逻辑搜索／正文任务最多一次瞬态重试，仍消耗同一服务或正文总额度；
此限制不重定义既有模型网络重试策略，模型仍受其子上限及基础／复核／父池限制。
鉴权、余额等非瞬态错误不原样重试；DeepSeek 的可重试状态按官方规则处理。
Tavily 默认 basic，关闭自动升级；高级搜索或提取仅由显式冻结配置选择，不能因结果不足自行升级。
计量保留服务原生 usage／credits、深度和计费版本；未知不填零。金额仅在已知价目和币种下估算，
不把请求上限宣传为精确的费用承诺，也不把账号级 QPS 当成 run 预算。

## 8. 记录、快照、数值绑定及兼容

新增独立的工作流／策略身份及 `ResearchRecordV2` 契约，保留 V1 的解析和旧执行链。
实现时登记具体常量，不复用已有 V7 身份；历史 V8 方案文档不代表已发布身份。
新记录使用一条哈希绑定、只追加的证据快照链，版本从 0 连续递增，最多八个快照：
初始一个、原有确定性验证最多一个、三轮各最多一个材料快照及一个派生检查快照。
没有变化不创建新快照；每个子快照包含父版本全部证据，旧证据对象不可修改。

新增材料、准入结果、阶段输入、派生数值、验证计划、复核输出和综合分别绑定实际输入快照。
保留原始假设、条件和原计算；新增检查以新计划和输入版本运行，不能把旧验证伪装成已使用新数据。
发生数据更正时追加替代关系及新计算，当前有效视图排除被替代值，历史引用仍可重放。
未受新增材料影响的原推断保留其有效输入版本，不要求无关专项重跑；受影响的推断
必须有适用复核才可作为更新后的判断依据，否则保留待核查状态。最终说明未审阅的新材料／冲突。

现有 `snapshots[0]`／V0→V1 假设、有限来源族、数值 catalog／F02 收据、局部检查、
回应绑定、Reader 校验和导出都必须为新策略提供显式版本分支。
新的来源按能力、字段与准入证明参与计算和专项视图，不能只放宽来源字符串白名单。
schema 版本、来源标识或策略身份篡改都应被拒绝，不允许伪装成旧记录。

每个请求、轮次、证据版本和模型尝试使用包含 run、阶段／轮次、问题或输入哈希的稳定标识。
恢复读取已保存成功、失败和未知派发，不重新搜索或获得新额度；输入变化不能复用旧输出。
凭证只在忽略的本地配置中，日志及研究记录不保存凭证、敏感请求头和 credential URL。

## 9. 用户可见行为与配置

新 Web 单公司和批量子研究使用新策略；旧 run 的读取／恢复仍按冻结策略。
DeepSeek 搜索默认使用官方工具端点及 `DEEPSEEK_API_KEY`，不跟随模型代理 base URL；
Tavily 沿用现有密钥配置，轮换不重置 run 预算。缺密钥按对应服务不可用处理。
新额度、超时、查询模板、搜索／提取深度和端点身份在 run 开始冻结；首版不新增预算编辑 UI。

Reader 展示证据及恢复情况，过程详情展示初始双路、失败回退、每轮缺口／新增材料、
受影响专项、预算用量和停止原因。正常研究页面使用研究语言；HTTP 调试明细留在审计层。
Reader、Markdown 和历史查看只消费保存记录，不发起搜索或模型调用。

## 10. 验证与交付条件

先离线验证契约和恢复，再考虑经过授权的有限真实调用；设计阶段没有运行付费调用。

必须覆盖：

1. 新闻／行业首次进入双路搜索；身份／财报优先接口，字段缺失和接口链失败触发一次相应回退。
2. 搜索回收的合格字段真正进入计算；错误公司、报告期、单位、预测／实际混淆、历史可知性失败被拒绝。
3. 新网页材料进入正确专项，重复和转载不增加信源，长正文受界限约束，非相关材料不触发复核。
4. 两家分别到第 50／51 次，正文第 8／9 次，补搜第 3／4 轮、复核第 9／10 次、总模型第 21／22 次的边界。
5. 并发预留、失败／重试、不同密钥、重定向、取消、时间耗尽、断点恢复和未知派发不能绕过额度；
   搜索发现 URL 的非公开目标、重定向到非公开目标、过大文件和超页数文档被拒绝。
6. 基础池与复核池互不借用；所有外部请求进入父账本；批次活动计时在并行、重启和模型推理间正确累积。
7. 新快照篡改、输入快照与输出不符、跨专项引用、复用旧验证或旧数值收据、撤回推断继续支撑判断均被拒绝。
8. 三轮内新增事实引发修正／撤回／新风险，未解决 critical 项和复核失败仍限制最终判断；无增量提前结束。
9. 老 V1／V7 的读取、校验、恢复及 Reader／Markdown 不变；新契约贯通 API、前端、发布及导出。

适用检查包括文档校验、相关 Python 测试／Ruff、前端契约测试／typecheck／build，
以及覆盖搜索进度、降级和旧记录读取的必要端到端场景。修改前端须同步生成静态资产。
通过工程检查不等于覆盖或研究质量提升；真实质量需要有限样本比较新增有效证据、
数据恢复准确性、时间可用性、判断修正、延迟和实际用量，不以链接数量代替。

## 11. 交付边界

本次是一条贯通的研究检索能力，不附带更换财务供应商、交易功能、用户数据清理、
付费 OCR、全网爬虫平台或独立 Tavily Research 产品接入。
实现须同步当前架构、证据研究操作文档、契约及两种语言的产品说明中实际变化的部分。
设计冻结时尚未改运行代码、预算默认值或线上服务；后续实施结果由现役合同和收尾记录说明。
