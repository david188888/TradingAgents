# 问题优先的双栏 Reader 与研究贡献说明

Status: Proposed

Do not use this document as evidence of current implementation behavior.

用户已于 2026-10-06 确认 [B2 阅读草图](../prototypes/2026-10-06-question-first-reader-b-v2.html)，并要求继续、简明解释各区域来自哪些 agent 或代码环节。本规格将已确认的视觉方向转为工程边界；当前生产行为仍以代码、ARCHITECTURE.md 和 operations 文档为准。

## 1. 目标与边界

读者缺少金融基础。页面必须让他能回答：系统回答了我的什么问题；哪些事实支持回答；最大疑点是什么；已经核对什么；下一步应查什么。继续追溯时能找到具体事实、保存原文及生成/校验环节，不需要先阅读 JSON 或理解审计术语。

本次覆盖 `evidence_v1` 公司研究、催化研究与持仓复盘的报告、证据、过程和相关审计投影。估值和量化保留当前计算、输入、适用范围与详细入口；旧 classic/catalyst 记录继续原读取路径。左侧新建研究配置在阅读结果时可收起，沿用现有工作台状态，不新增分析模式。

本次不改变 agent 数量、角色输入隔离、prompt、流程默认值、预算或恢复身份，不自动取新数据、运行付费模型、修复/重写历史报告，也不规定“强关联”的新数值门槛。允许增加不参与 prompt/恢复身份的观察覆盖标记，确保未来运行能证明调用记录完整；旧数据不被回填为完整。公告 PDF 解析故障在本轮解释与定位；依赖安装、数据重取和研究质量改进是独立工作，不能靠改版升格历史结论。

## 2. 必须保持的约束

- 已提交且校验通过的 `ResearchRecordV1` 是研究内容权威。Reader 打开、切换、跟随或查看解释均不生成新研究事实。
- `run.status`、`assessment.completeness`、`assessment.quality`、局部检查状态分别展示，不能把 `complete / LOW_CONFIDENCE` 写成统一的“部分研究”，也不能写成“问题已解决”。
- 提出核查、保存模型提议、执行代码检查、取得新增来源和回答经济命题，是不同状态。
- 缺少正文、来源不合格、未执行核查、反面证据和程序故障分别表达。专项没看到材料不等于全局没材料；相关字段或出处存在不等于它能证明经济判断。
- 角色归属不加入独立挑战 agent 的输入，保留其上下文隔离。对读者的贡献说明是读取投影，不参与模型推理。
- 未记录的调用、Token、耗时和归属显示“未记录”，不得填 0。只有完整记录能证明零时才显示 0。
- 报告不得因视觉文案、引用数量或调用次数而提高结论强度。

## 3. 页面区域与真实来源

| 区域 | 主要来源 | 代码的贡献 | 呈现边界 |
| --- | --- | --- | --- |
| 研究问题与回答 | 请求保存的问题；综合 agent 的 `assessment.judgement` | 身份、维度与发布校验；综合不可用时生成明确降级回答 | 展示原始问题与已发布回答，草图简短改写不覆盖原文 |
| 为什么得到这个回答 | 三专项的推断和代码取得的事实；综合选择 `key_claim_ids` | 检查事实引用、专项输入资格及关系引用 | 事实/推断分开，每条能进入支撑事实与附着来源 |
| 最大的疑点 | 独立挑战的 `statement`；综合选择 `primary_challenge_id` | 必要时把关键挑战置于首位；保留未解决状态 | 来源说明区分“谁提出”与“谁选为重点” |
| 下一步怎么查 | 主挑战的 `proposed_test`；综合的 `next_check` | 呈现已执行检查、失败和命名范围 | 拟核查不显示为已执行；完整综合建议仍可查看 |
| 估值定位 | 已冻结估值输入与确定性计算 | `native_valuation` 组装，估值链复算与资格校验 | 经营 agent 可解释估值，参考区间不是由它随意报出的目标价 |
| 量化背景 | 已保存行情、复权与日历，以及确定性统计 | 计算波动、历史尾部收益、回撤和 ATR 等 | 市场 agent 解释背景；计算不是模型估算，也不能证明业务关系 |
| 证据核对 | `claims`、`supporting_fact_ids`、`evidence_ids`、保存内容 | 安全来源、时间、哈希、身份与关系校验 | 附着来源仅表示被引用；不自动宣称全部直接支持推断 |
| 研究过程 / 技术诊断 | 角色事件、经过完整性检查的 checkpoint、已提交结果 | 聚合状态、提议/发布区别及分口径计数 | 完成与有效性分开；不展示内部思维或完整私有 checkpoint |

### 本次 002130 示例

保存运行 `run_20261006T080541489282Z_c275dbb3` 的主疑点目标，是经营质量专项的一条推断。对经过哈希校验的 checkpoint 按原 ID 规则复算，可确认它来自 `operating_quality`；不能只根据文字内容猜角色。

链路为：经营质量专项提出“整体财务不能证明 AI 业务贡献” → 独立挑战要求按产品/客户/行业核对收入与订单 → 代码的 `operating_disclosures` 检查为 `unavailable` → 综合选为最大疑点并提出下一步。

本次保存的 `next_check` 另含 AI 基准、Beta/相关性建议。正式 Reader 保留它，并说明这是价格联动背景，不能替代业务证据。草图中整理出的三步不是历史模型的逐字产物。

## 4. 报告与证据交互

### 报告结构

依次展示问题与当前回答、关键依据、最大疑点与下一步、估值、量化。原问题可展开。根据保存的请求 metadata 标明“你的研究问题”或“系统默认研究问题”；metadata 不足时使用中性“本次研究问题”，不根据问题措辞猜来源。当前回答使用已保存 `judgement` 的完整文本，正文尺度与行距承载较长回答，不机械截断或用客户端新总结替代。

最多三条重点依据，按保存 `key_claim_ids` 顺序展示；同一结论不在每个区域再次放大。依据没有记录时显示明确空态。全部关键挑战仍须通过“其他重要疑点”可达，不能因为首页只突出一条而丢失。

报告末尾保留“完整研究记录”入口，可进入所有维度判断及其引用、全部 claims、全部假设及成立/推翻条件、所有等级的挑战、全部代码检查与独立执行、全部量化指标、全局/专项限制和保存来源目录。未进入首页的条目仍可按 ID 追溯；催化兑现与原持仓假设作为模式对应维度保留，不能用估值或量化替代。详情使用分区/按需展开，避免首屏恢复全量铺陈。

下一步默认展示与主疑点直接绑定的 `proposed_test`；没有主挑战时使用 `assessment.next_check`。二者不同且均存在时，次级展开显示“综合环节的完整建议”，逐字保留 `next_check`。二者相同则只展示一次。检查结果另标“已经核对”，保留局部检查的问题、状态、限制及结果；独立验证只根据 `verifications` 显示，不用挑战处理意见代替。

每个区域提供折叠的“这部分如何形成？”：默认用中文说明取数、分析、挑战、选择重点和代码校验的不同作用；能恢复准确归属时显示实际归属，无法恢复时显示栏目级方法说明并标“本条角色归属未记录”。

### 宽屏与窄屏

宽屏采用 B2：左侧报告，右侧相关证据。容器保留当前工作台设计 token，主区不被两侧面板挤至无法阅读；可用宽度不足时转单栏，依据通过抽屉打开。以内容容器宽度为判断依据，侧栏展开造成空间不足也应降级，不只判断浏览器外窗宽度。

正文以约 15–17px、1.75–1.85 行距为起点；问题与章节标题、卡片标题、正文和元数据有稳定层级。根据真实嵌套容器截图调整，不以具体像素宣称阅读验收通过。支持系统减弱动画与文字放大；移动布局不隐藏关键内容。

证据选择绑定 claim、challenge、check、metric 或 valuation 的实体 ID 与触发区域，不只绑定来源名称。随阅读位置切换时优先选择跨过阅读基准线的当前区域，避免长段落未读完就切到下一模块；显式选择会固定；右栏悬停、内容获得键盘焦点或展开原文时暂停自动切换。提供恢复跟随、回到对应实体判断和放大。跨运行重置选择；依赖 run_id 校验阻止旧请求内容进入新运行。Tab 顺序符合阅读顺序，模态抽屉封闭焦点、Escape 关闭并恢复触发按钮；按钮消失时回到稳定证据入口。

### 证据内容与概念解释

先显示当前判断、绑定的支撑事实、来源时间/报告期和单位，再显示保存原文。只对识别的字段与来源结构进行确定性格式化，人民币转元/万元/亿元并保留完整值。财务摘要以绑定事实为范围，不能把同一 JSON 中所有季度或额外字段当作本条依据。

已保存正文显示原文、页码/定位和截断提示；未知字段格式、未保存内容与解析失败各自降级，不调用摘要模型。原始 JSON、完整数值、哈希和技术元数据折叠。公开链接沿用安全校验；不把配置、token、完整 prompt 或 checkpoint 放入 Reader。

术语来自有限代码维护词典，优先覆盖合并口径、归母净利润、经营现金流、估值锚点、PE、PB、波动率、回撤、ATR 和条件核查。解释是一般方法知识，不是新增公司事实；不自动生成“因此这家公司……”式经济结论。未知术语保留原文。

## 5. 贡献与过程投影

新增只读 `GET /api/runs/{run_id}/reader/process`，由 Web 层的过程模型/投影拥有；不改变领域 `ResearchRecordV1`、模型 prompt 或持久化工作流版本。TS facade 镜像 Python wire contract，hook 拥有请求与跨运行状态，叶组件只消费 typed 数据。

过程响应携带 run_id、source_sequence、profile/workflow、读取资格、6 个原生角色状态、分口径计数、可公开的产物数量/链接以及已验证的归属引用。它不是新的研究记录，不能单独填入最终判断。缺失运行沿用 404；非原生记录返回明确不适用；缺 checkpoint/未知版本/损坏返回局部或不可用及原因，保留可读的事件状态，绝不回填。

投影读取 snapshot、事件和 `load_checkpoint` 检查通过的 checkpoint，采用有限字段白名单：角色、状态、计数、公开实体 ID 和固定安全原因。checkpoint 中的任意文本、完整模型提议、输入及配置都不直接透传。

一致性读取以首次 snapshot 的 `latest_sequence` 为边界；事件、checkpoint 和已发布 record 都只选该序列或之前的 committed 项。给现有完整性读取增加可选序列上界，默认调用保持当前恢复语义，不复制一套无哈希检查的加载器。响应 `source_sequence` 就是该边界。读不到该边界的产物时返回明确局部/不可用，不把更新 checkpoint 与较旧 record 拼成一份“完整”响应。

前端新增 process hook：首次按 runId 请求；用既有 SSE 的角色/产物事件序列触发刷新，角色变化尽快刷新，密集 checkpoint 事件最多每 2 秒合并一次；终态事件立即进行最后一次读取。接受响应须匹配 runId、请求代次且不低于已接受的同运行 `source_sequence`；响应低于已看到的事件序列时安排一次后续刷新，不能停留在首次结果。SSE 断连时使用 5 秒只读轮询；隐藏页面暂停轮询，回到前台刷新。终态且响应追上终态序列后停止；最后读取失败按现有 transport 有界重试，仍失败显示可重试空态，不持续无界请求。跨运行取消旧请求并重置序列、选择与焦点状态。

已发布的记录通过现有研究记录投影校验后，才可提供正文和判断链接。运行中只提供阶段目的、状态、预计产物类型，以及能够独立证明的安全计数/取数失败原因；已缓存模型内容只记为“结构化提议已保存”，不作为已发布研究判断。没有合格公开产物时明确说明等待发布校验。

角色归属恢复仅支持已知原生版本：检查 record 和 checkpoint 的 run、ticker、日期、模式/版本身份，以及保存 `native.output` 的内容摘要与已提交 record 一致；再用保存 `native_input`、角色、序号和合法 proposal 按原核的 ID 规则复算，映射到真实 claim ID。引用必须属于已发布 record。多义、不匹配或不支持版本返回未记录，不能按关键词、数组位置或当前路由推测。固定栏目来源（综合、挑战、代码计算）与逐条角色归属分别标注。

支持版本配对为：`evidence-production-v1/v2` → `native-research-kernel-v1`；v3 → kernel-v2；v4 → kernel-v3；v5 → kernel-v4。必须检查保存的配对与生成规则，不把当前 v5 规则套在未知版本。主疑点如被关键级别保护规则置顶，说明“挑战 agent 提出，综合选择/代码置顶”；根据保存的综合提议与最终 ID 判断，不全部归为综合的主动选择。

核查是代码工作，不额外伪造一个 agent 或角色状态。六角色为证据、经营、事件、市场、独立挑战、综合；UI 可以将三专项组合为阅读步骤，但展开后显示各自状态，不能把 5 个阅读步骤说成 5 个全部执行节点。`evidence_checks` 在冻结证据阶段计算；挑战后绑定与评估；`verifications` 才表示额外的有界条件执行。

## 6. 调用与审计真实性

审计按 `roles_for_profile` 选择原生、catalyst 或 classic 注册表，原生导航使用实际阶段，角色详页与汇总共用同一投影。现有 Audit 保留仅终态可访问的边界；运行中使用研究过程入口，界面不会发起必然 409 的审计请求。

原生模型统计优先读取 checkpoint 的 SDK 发出授权：主调用由 `native.model.<stage>.dispatched` 标记，修复调用由 `structured_repair` 已 dispatched 的唯一 attempt 计数。主分析预算的 `main_analysis` 授权计数单独保留，不能等同实际 SDK 请求。网络送达、完成和计费未知时明确未知；发出授权不宣称供应商已接收。

数据能力调用与 `data_http_attempts` 分开。reserved/released 未发出项不计为发出；重复 checkpoint、恢复、缓存重放不重复计数；未知但已 dispatched 的预算消耗保留。没有 SDK 标记的旧记录可展示已知预算尝试，并将 SDK 数显示未记录。不存在 `model.*` 事件不能证明 0 模型调用。

每项计数同时携带值、范围、来源与完整性（完整 / 已知下界 / 未记录 / 不可用）。旧 checkpoint 的哈希、版本和形状合格，不足以证明 SDK 标记覆盖完整：有标记的数量可显示“已记录 N 次”，完整性未证明时为已知下界；无标记且覆盖未知时 value 为 null，不显示 0。总计只有全部分项完整时是准确总量；存在非完整项时展示明确“已记录小计”及下界资格，全无可知项时为 null，不能用 null 当 0 相加。

为未来运行增加代码拥有的 `native-sdk-authorization-observation-v1` 覆盖标记（契约与验证由 runtime 拥有）。NativeModelCaller 在 NativeRunner 构造 delegate 时的初始化边界持久化标记及覆盖起始序列，必须早于 kernel 首个 MAIN dispatch；只有此前无已 dispatched 主/修复尝试且后续所有 SDK 路径均受该协议记录时，才证明全程覆盖。恢复时不能覆盖性地追认旧尝试；若此前存在未覆盖尝试，仅后续部分受新标记覆盖。测试替身或未知 adapter 没有协议，不能因为当前 workflow 是 v5 就视为完整。读取投影不写标记。记录完整且主初始化失败、无 SDK 标记的阶段可以显示 SDK 0、主预算授权 1；没有覆盖证明的同样记录显示 SDK 未记录。这不改变预算/业务流程版本，也不新增模型或取数。

对应 Web 审计模型将不能证明的调用/turn 计数变为 nullable，并增加记录依据/资格；所有 TS 消费者、总计、角色详情与空态同步更新。旧兼容 API/Reader 的缺字段按明确兼容规则降级，不以类型转换掩盖 null。Token 与时长缺失不填 0。

技术记录折叠显示“用于检查执行、来源故障和可追溯性”；checkpoint 保存次数与研究成果数量分开。现有禁止下载/展示 checkpoint 和敏感输入的规则继续生效。

## 7. 实施分层与顺序

1. Web 过程/审计投影与 canonical DTO：先落实记录资格、原生角色、计数语义、归属与白名单；复用完整性读取，拒绝把投影写入运行状态。
2. 前端资料选择与格式化：用实体 ID 组装已保存事实/引用视图；有限术语词典和方法说明；不把原生路径混入旧 Reader。
3. 原生报告/证据/过程组件与工作台整合：实现 B2 布局、容器响应式和焦点；原生 running/failed/cancelled/interrupted 使用真实状态、既有取消/恢复功能。
4. 保留估值组件、量化方法和细节入口；同步 current-state 文档，重建并纳入 tracked static assets。

不会先写硬编码沃尔核材专用页面，再用字段填空适配其它公司。

## 8. 验收与停止条件

离线与已保存运行验收优先，不新增真实取数或模型请求。存在的 pytest/Vitest/Playwright scaffolding 按 owning layer 使用；公共 docs、Ruff、frontend ci/typecheck/build 和 diff 检查依仓库指南执行。
