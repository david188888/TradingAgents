## 1. 目标与已确认范围

用户已确认继续 research-only，同时重构催化研究、通用公司研究和持仓复盘。目标是提高最终 LLM 判断的准确性、证据利用与可回溯性，并降低读者理解和核查结论的成本。

“研究优先级”不能代替具体判断。系统需要回答研究问题，例如经营改善是否得到支持、估值是否依赖过强假设、催化是否兑现、原持仓假设是否被削弱。输出仍为研究判断，不生成买卖指令、仓位或订单。

最终目标不能简化成更少 Agent、更多引用或更短报告。它们只有在不降低判断质量、重要反证覆盖与可读性的条件下才有价值。

## 2. 第一性原理

一次错误判断可能来自六个环节：取错或取不到数据；数据的日期/单位/复权错误；把披露或观点当成已发生事实；事实到推断缺少传导条件；遗漏关键反例；压缩输出时删掉会改变结论的限制。

因此研究内核与阅读界面必须一起设计：每个阶段保留可检查的输入、输出和理由，展示层不能增加、强化或重新生成结论。

基本不变量：

- 来源内容、事实、推断、假设与验证结果分开；引用存在不代表引用能支持该主张。
- 转载不计为多份独立支持；官方计划只证明披露了计划，不证明执行完成。
- 研究截止之后才可知的信息不能进入历史研究；同一输入版本可重复重算。
- “没有证据反驳”不等于“已验证”；不能验证必须显式保留。
- 身份、时间资格或核心引用错误阻止相应结论发布；维度性缺失只限制相应判断。
- 展开、刷新、重连与导出均读取已提交产物；不触发模型或取数。
- 历史产物保持历史语义，不能补成看似真实的新证据。
- 外部文本视为研究材料，不执行其中的指令；不把外部内容带入系统权限。

## 3. 三种路线与推荐

| 路线 | 优点 | 代价 |
|---|---|---|
| A：共享证据/计算/验证/发布内核＋模式政策，推荐 | 三类研究统一质量与阅读契约，保留问题差异 | 需要版本化接口及全链迁移 |
| B：分别继续优化 classic 与 catalyst | 短期对单一路径干扰小 | 易形成两套证据、指标、预算与阅读逻辑 |
| C：一次性整体重写 | 可以重新设计全部实现 | 质量退化难定位，历史兼容和回滚代价高 |

选择 A 意味着全范围统一设计、按依赖分批实施。不是仅改 catalyst 后宣布通用研究完成。

## 4. 统一研究流程

```text
请求/研究问题/截止与展望
  → 能力计划与供应商准入
  → 原始证据版本 V0 / 事实提取 / 代码计算
  → 独立专项与假设
  → 一次挑战
  → 有界工具验证，生成 V1 增量与验证记录
  → 一次最终综合
  → 确定性约束与引用校验
  → durable 提交
  → 同源 Reader / Markdown / JSON
```

验证新增材料不能改写 V0。V1 记录新增来源、截止资格、被验证的问题及关联假设。专项成果保留原输入版本；最终综合明确使用 V0、V1 与验证状态。验证失败或超预算不再次无限循环。

### 4.1 职责与模型调用

三个分析职责：经营/财务质量；事件/行业与预期变化；市场/估值背景。每个职责回答模式指定的问题，读取合格证据和代码计算，输出受限数量的原子主张和假设，不写重复公司全景报告。

新闻、社交、情绪是输入能力。只有问题需要且有合格材料时才进入分析；不固定创建 Sentiment Agent。能力不够时不让角色凭空填报告。

专项不读取其他专项的初步判断。挑战者看到假设、依赖事实与必要原文，但不看最终评级、研究优先级及作者身份。这样减少结论锚定，同时允许事实核查。共享来源或共享模型仍可能产生相关错误，不能称为统计独立。

风险类型采用代码维护的覆盖清单；挑战阶段检查最关键的证据、经营、治理、市场和估值风险。没有实质反例时允许零挑战；未知项可独立存在，不强迫生成反方观点。

验证器默认是工具与脚本执行器，不是新增自由聊天 Agent。允许检查原文、查询已准入能力、重算数字、比较披露版本。模型仅在确有非结构化材料时承担受预算约束的提取。最终综合输出一次，并逐条处理关键挑战。

正常主模型路径最多三次专项＋一次挑战＋一次综合；可以跳过无必要或无资格的专项。语义预处理、验证提取、修复、网络重试和分页全部单独计入现有预算分类；新流程不得绕过持久化许可和恢复计费。确切数值在接口设计时核对现有账本，任何新增额度需明确批准。

### 4.2 三种研究模式

| 模式 | 核心问题 | 首要输出 | 特定输入 |
|---|---|---|---|
| 催化研究 | 窗口内什么变化可能改变判断，如何兑现？ | 催化状态、兑现链、未解决约束、观察触发 | 已知事件及进度、财务、价格/成交背景 |
| 公司研究 | 经营质量/前景如何，当前估值需要什么假设？ | 经营判断、估值情景、主要风险、推翻条件 | 财务版本、业务材料、估值与适用同行 |
| 持仓复盘 | 原假设哪些成立、削弱或失效？ | 假设变化、原因和下一复查条件 | 用户提供的原假设及截止一致的旧 case |

现有 catalyst 的 84 天展望保留为该模式的默认政策，不强加给公司研究或持仓复盘。历史回看窗口与未来展望分别记录。持仓上下文缺少原假设时显示“无法核实原假设”，允许研究当前公司事实，但不编造当初持有原因。

## 5. 最终判断契约

“判断”由四项构成：回答研究问题的一句话；适用时间窗口；直接支撑/限制该判断的主张；可推翻或改变判断的条件。

按维度表达，避免一个总分掩盖差异：

- 经营与前景：改善/稳定/承压/无法判断，必须给具体依据。
- 估值：当前价格相对显式假设参考区间的位置；无合格输入则不可用。
- 催化：进度、已知约束和兑现状态，不把宣布当完成。
- 持仓假设：支持/削弱/失效/无法复核；因模式而异。

综合研究倾向可以保留 favorable/neutral/cautious/insufficient_evidence 等现有语义，但须指向上述维度和适用窗口。不能把覆盖率算成判断准确率，也不在首屏显示未经校准的“准确率 85%”。

代码限制结论可发布范围，不冒充语义真值裁判。关键挑战无法解决时，依赖该假设的判断必须降为条件性或暂不判断；其他有证据的事实仍可展示。数据齐全或运行成功不意味着结论正确。

## 6. 证据怎样真正得到利用

在现有 canonical models、research-package 与 catalyst artifacts 上演进，不另建独立事实库。

| 实体 | 必需内容与关系 |
|---|---|
| 来源 | source ID、身份、发布时间/获取时间/可用时间、内容哈希、来源家族、版本、安全公开链接 |
| 事实 | fact ID、原子陈述、原文页/段定位、来源 ID；数字附单位/期间/口径 |
| 派生计算 | 输入 evidence IDs、方法版本、窗口、样本数、结果/单位、质量与原因 |
| 假设 | 依赖事实、传导条件、替代解释、支持与反驳材料、失效条件 |
| 挑战/验证 | 目标假设、检查办法、输入版本、执行结果、支持/反驳/未解决及原因 |
| 最终判断 | 生效窗口、关键依赖、限制、观察触发、发布资格 |

从 final judgement 可以反向走到原文；从一条 evidence 可以看到它影响的主张、假设和判断。复查时保留新增/撤销/更正，不直接覆盖旧记录。

检索不按关键词相似度单独排序。先按研究问题、标的、时点、来源资格和依赖关系筛选，再为关键支持及反例各留上下文额度。长文采用可回溯的分块提取；禁止压缩时丢掉否定、条件、单位或期间。

证据“可靠性”拆成来源身份、覆盖、时点资格、提取质量和主张支撑，不使用一个 LLM 自报分数替代。企业披露包含立场；公开披露身份与业务结果可信程度分开。

## 7. 数据和量化

数据计划按能力匹配来源，不从供应商名单无界遍历。显式供应商选择保持有效；替代来源必须满足同一数据口径和用户策略。限流、权限、网络错误、合法空集、缺页与无效载荷分别记录。

优先补齐有界合格价格历史与财务来源。a-stock-data 作为实现参考，端点可用性与 PIT 资格需要本地验证。当前 catalyst 无默认合格行情路径是实际缺口，不能靠取消门控得到 PASS。

量化使用已有 risk_metrics.py、valuation.py 和输入装配：先修初始财富最大回撤与跨缺失日期收益口径，再接入生产。保持市场风险与估值分开：

- 风险：σ、历史 VaR/ES、beta/相关性/拟合质量、ATR、最大回撤，逐指标按样本/基准/OHLC/复权资格降级。
- 估值：历史/同行 PE、PB 分位、同口径盈利和净资产锚、情景敏感性。净利润、TTM、年度、每股值和股本必须一致。
- σ、VaR、beta、ATR 与价格分位不直接形成内在价值；参考区间不是统计置信区间，不用区间中点伪装精确目标价。
- 所有指标记录方法/输入版本、日期窗口、样本数、基准、单位和局限。单日 VaR 不直接按 √84 转成催化窗口 VaR。

## 8. 阅读布局：从理解到核查

推荐单列主阅读区，原文按需打开。沿用现有 tokens、焦点/抽屉机制和安全公开投影；不重做视觉主题。

| 位置 | 默认内容 | 设计理由 |
|---|---|---|
| 页头 | 公司/标的、截止、展望及系统确定的研究范围；本次新增变化 | 防止错公司、错日期、错窗口；复盘突出变化，无模式或状态选择器 |
| 判断区 | 一句有条件的判断；经营/估值等适用维度 | 第一眼回答研究问题，避免先读流程状态 |
| 紧接判断 | 最大反证或关键未知；阻断限制直接展示 | 读者尚未形成锚定前就看到结论边界 |
| 核心依据 | 最多三条高重要性主张，各自事实/推断标签与引用 | 优先减少错误推断，不按文章数堆砌证据 |
| 首页量化摘要 | 条件性估值参考、σ、VaR、beta；短标注窗口/基准/单位 | 将计算结果用于理解判断，完整方法与输入仍在详情，不堆放指标全表 |
| 下一观察 | 事件/日期/阈值 → 为什么改变判断 | 给出可执行的研究复查条件 |
| 判断详情 | 假设链、反例/验证、估值情景、量化背景 | 支持数分钟的深入理解，避免多份摘要重复 |
| 引用面板 | 原文摘录 → 已保存摘要 → 支持/不能支持；来源与页段可展开 | 直接读到定位内容，页码只是辅助；保留原文与解释的区别 |
| 研究过程/审计 | 来源覆盖、阶段状态、调用/成本、失败与历史兼容 | 放在次级入口，需要排查时可用 |

研究优先级是小型辅助项，不占主要标题。运行完成、数据完整、判断可用性分别表达。“已发布”不能用作准确性标签。

首屏目标正文约 250–400 中文字，为阅读目标而非刚性安全截断。重大限制不计入压缩预算，不能被更多/折叠、标签数或手机滚动裁切隐藏。手机按同样顺序纵向阅读，允许页面滚动。

宽屏不常驻第二篇报告；引用面板按需打开，窄屏使用可关闭的模态面板。键盘可达、Esc、焦点返回和背景 inert 复用已验证机制；颜色必须配文字含义。

首页量化摘要排在判断、重大反证和核心依据之后，下一观察之前。首页不是固定像素内塞满信息，手机允许自然滚动。估值与市场风险分开标明：前者依赖盈利/倍数假设，后者描述收益分布，不能用 σ、VaR 或 beta 证明低估。默认至多四项，不按阈值自动染成买卖信号；窗口、收益口径、基准与缺口不可省略。ATR、ES、quantile 等完整表进入详情，只有特定研究问题需要时才提升到摘要。

估值详情先显示方法、假设和区间，再显示当前位置；无数据时显示缺口，不能留一条看似存在但没有数值依据的估值尺。引用面板的原文摘录来自已有证据底稿；摘要是明确区分的派生内容，展开不重新调用模型。缺少摘录时诚实显示未保存原文，不能把生成摘要冒充引文；页码、期间和披露版本保留在可展开来源信息中。

## 9. 展示状态与模拟样稿

按本轮反馈，样稿取消研究模式和展示状态选择器，默认展示含经营、估值、催化与风险的公司研究。产品方案采用一个默认研究入口；持仓复盘以实际提供的持仓/原假设上下文为前提，不能补造。研究范围和可用状态由请求上下文与已验证运行产物决定，用户不手动选择状态。默认入口不能把缺失资料或失败强制展示成成功。

样稿当前固定使用一份人工构造的条件性判断材料。其首页风险数字确实由 [离线脚本](../prototypes/reader_sample_metrics.py) 从固定模拟日收益计算，[输入与结果](../prototypes/reader_sample_metrics.json) 保存方法、样本数、输入 hash 和限制；这是可复算展示，不是合格真实行情或真实研究能力证明。估值仍是演示 EPS × PE 算术。运行状态的下列退化规则保留在实施与测试要求中：

- 条件性判断：有事实与计算，保留未兑现假设；不要将未解决未来问题当成验证完成。
- 关键资料缺失：保留已证实事实，在顶部说明哪些判断不能形成；估值模块保持不可用。
- 身份无法核验：不形成实质公司判断；显示阻断原因与恢复研究所需材料。

引用面板显示模拟原文及“支持/不能支持”；验证详情区别指标事实已核查、具体假设被反驳、重算已完成和未来待观察。净经营现金流不能直接替代销售收款或回款效率。持仓视图保留模拟用户于 2026-06-30 提供的 H0：2026H1 收入若同比增长，经营现金流净额也应同比增长；同期间两指标可检验这个具体假设，不延伸否定长期经营前景。交付计划只作背景，不参与 H0 判定。不能把旧报告未写明的理由补造为原假设。

## 10. 如何证明“更准确”

事实正确、解释有依据与预测正确是三个不同评估目标。

第一阶段使用同一截止、同一冻结证据的旧流程/新流程/简单单模型基线对照，控制模型版本与预算，审阅时隐藏流程名称。手工标注关键事实、支持关系和重要反证；LLM 裁判仅用于筛查，不能作为唯一真值。

第二阶段再比较真实取数链路，此时单独报告证据覆盖改善，避免把“拿到更多资料”的收益归因于辩论结构。首批建议 30 个混合案例（每模式 10 个，包含缺数据/矛盾/失效），是试点而非统计优势证明；真实模型费用和语料获取另行确认。

| 评估 | 方法 |
|---|---|
| 事实与数字错误 | 人工依据原文与手算/独立计算核实 |
| 引用支撑关系 | 结论是否超出引用及条件，转载是否重复计数 |
| 关键反证遗漏 | 预先标注会改变结论的事实/条件，不用“有风险章节”代替 |
| 判断恰当性 | 专家/用户盲评是否回答问题、是否因证据不足合理暂缓 |
| 预测质量 | 仅对预先声明的可结算假设，在展望结束后评估；未来结果隔离 |
| 校准 | 只有足够样本的可结算概率预测才使用 Brier 等；不校准自由文字自信 |
| 成本与稳定性 | 记录实际调用、tokens、延迟；固定证据重复运行比较结论波动 |
| 阅读效率 | 读者能否约 1 分钟复述判断和最大反证、约 2 分钟定位核心原文 |

验收不能靠收益率一个数字，因为本系统不定义交易动作，且短期价格与经营判断可不一致。不能为了降低幻觉而让所有案例永久“无法判断”；同时评估合理给出判断和合理拒绝判断的能力。

工程硬门槛：身份/时间/引用完整性；确定性计算；关键挑战不可静默丢弃；恢复预算不重置；串并行汇合稳定；读取零 dispatch；旧数据降级诚实。软质量改善必须通过上述对照，暂不预设凭空的准确率提升承诺。

阅读验证包括正文和严重限制、引用原文定位、三模式、缺数据/阻断、390px/常见桌面及 200% 缩放；真实浏览器与用户阅读验收分别记录。静态样稿通过不代表产品实现或真实研究通过。
