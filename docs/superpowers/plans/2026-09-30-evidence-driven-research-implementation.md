# 证据驱动研究：分批实施与验收

Status: In progress — 方案与阅读样稿已认可，工程分批进行。

日期：2026-09-30。设计依据：[审查方案](../specs/2026-09-30-evidence-driven-research-and-reader-proposal.md)。基线 main `b68fee8`。覆盖公司研究、催化研究和持仓复盘；research-only。

## 实施顺序

### A. 数据与计算基础

- 修正 `dataflows/risk_metrics.py` 的初始峰值回撤和缺失交易日跨期收益；提供不依赖基准的波动率/VaR/ES计算，保留有基准时的 beta。
- 检查 Wind 已安装 CLI 契约，修复复权锚点、错误 envelope 和 EDB 工具名称漂移；逐接口记录小范围权限验证。
- 对 bounded 路径新增直接 Tushare `daily` + `adj_factor` + `trade_cal` 适配，所有请求经过现有 `fetch` 和 HTTP 账本。保存因子锚点、实际日期、缺口、算法版本和输入哈希。
- 截止日期因子不等于历史因子快照；历史检索不能无凭据标为 PIT verified。未具备条件的价格不进入合格专项输入。停牌/缺行不填成零收益。
- 用手算反例、离线供应商 fixtures、复权/交易日/身份污染、恢复和额度检查验证。真实查询只检查数据接口，不调用付费 LLM。

### B. 统一机器契约与证据利用

- 从 `agents/schemas/` 和 `research/` 开始，建立版本化的来源摘录、原子主张、假设依赖、验证记录、量化结果和分维度判断；明确经典与 catalyst 的迁移映射。
- 证据摘要标为摘要，摘录附原文定位及内容哈希；不得给旧 run 编造正文。来源家族去重、事实/披露/推断/假设分别表达。
- 量化产物由代码生成并持久化，包含方法/单位/窗口/样本数/输入引用/不可用原因。ATR 只用同基准 OHLC；估值分位只用一致定义估值历史；波动区间不能替代价值区间。
- 更新生产者、运行结果、durable store、恢复、Reader/API 投影和 TypeScript 消费者，同步 schema 测试，不能只新增 DTO。

### C. 共用研究内核

- 模式政策提供问题与必需能力；专项隔离初步结论；挑战可为空，最多一次，不设置用户可调辩论轮数。
- 挑战后执行有界原文查询/计算核查；V0 不可改写，新增 V1 及验证状态明确绑定假设。超预算/失败保留未验证状态。
- 三专项、一次挑战、一次综合复用 main 5 和现有 semantic/repair/retry/data/HTTP 账本。确定性预留角色额度，串并行输出顺序一致。
- 发布前校验身份、截止、引用、数值来源与关键挑战 disposition；缺失按依赖维度退化。请求、恢复、取消、检查点、SSE、CLI/Web 均覆盖。

### D. 产品 Reader

- 按已认可样稿：判断→最大反证→至多三条依据→量化摘要→展开细节。模式由请求确定，状态由产物确定。
- 引用面板优先摘录/已保存摘要，然后说明支持和限制；定位/来源在次级位置。读取、展开、刷新和导出不得 dispatch。
- Reader、Markdown 和 JSON 从同一已提交研究产物生成；旧 run 显式显示可用内容和缺失。
- 三模式、缺数据、关键挑战未解决、严重限制、移动端/桌面阅读验收；前端 typecheck/test/build，包含 tracked static。

### E. 对照与迁移

- 先固定同一证据比较旧/新流程，再比较真实取数效果；区分流程收益和新增信息收益。
- 人工核查事实、引用支持、重大反证、判断恰当性及阅读效率；记录成本/延迟/重复运行稳定性。完成代码不宣称准确率提高。
- 确认真实模型对照预算及语料后执行；通过验收才迁移默认流程。保留历史只读与回滚，不删除用户数据。上游 v0.5.2 逐项适配，避免整体 merge。
