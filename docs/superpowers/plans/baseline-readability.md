## 2. 重复字段与重复内容

### 2.1 跨容器内容重复（最主要的冗余源）

`view.brief` 与 `learning_summary` 的句子级重叠：

| 指标 | 值 |
| --- | --- |
| 重叠比例 min / **p50** / max | 0% / **96%** / 98% |
| >50% 重叠的 run | **14 / 15** |

即：**`view.brief` 中约 96% 的句子已经逐字出现在 `learning_summary` 里。** 读者在首屏会把同一段话读两遍。

实测样例（`run_20260821T115857528047Z_26e8bab1`，30 条重复句）：

```text
- 448G兑现时点依赖终端客户方案与Rubin量产节奏，属未定价的期权而非估值主体
- 经营恶化延续，跌破关键支撑触发去杠杆 002130.SZ 中期（12个月）趋势明确下行：
  区间峰值34.65（2025-09-25）回撤至谷底14.91（2026-07-20，-57%），现价16.29
- 或任何中报数据、448G批量定点、H股回购执行、收盘跌破14.91/站稳17.3等触发事件发生时即时复核
```

**这直接印证设计 §3 的根因判断**（「用户需要按研究问题的重要性阅读，当前系统按生产过程组织信息」），并给出量化：冗余不是「有几个 agent」的问题，是**同一投影被挂载两次**。

### 2.2 字段级重复

`reader-brief-v1.json` 各字段在 15 个 completed run 中的填充情况：

| 状态 | 字段 |
| --- | --- |
| **每个 run 都非空**（常显） | `risk_consensus`、`omissions`、`data_quality`、`debate_digest`、`execution` |
| 有时非空 | `learning_summary`、`research_rating` |
| **15/15 全为空** | `executive_summary`、`drivers`、`risks`、`catalysts`、`invalidation_conditions`、`analyst_cards`、`price_target`、`holding_review`、`evidence_refs` |

字段内**逐字重复**（同一字符串在同一字段出现 >1 次）：**0 例**。
`executive_summary` 与其他字段的句子重叠：**无法测量（该字段恒为 `null`）**。

### 2.3 ⚠️ 与设计 §3 的矛盾（必须上报）

设计 §3 表格写：

> 「learning_summary 的事实/推断/情景等展示后，**还会再展示驱动、风险、验证节点**」
> → 代码依据 `frontend/src/components/reader/DecisionBrief.tsx`

**实测：projection 里 `drivers`、`risks`、`invalidation_conditions` 在 15/15 个 completed run 中全部为空数组。** 同理 `executive_summary` 恒为 `null`、`catalysts` 恒为 `[]`。

两种可能，**本 agent 无法在不启动前端渲染的情况下判定**：

1. `DecisionBrief.tsx` 在**客户端**从 `learning_summary` 内部字段（`facts` / `implications` / `catalysts[]` / `downside` / `upside`）派生驱动与风险块 —— 那么设计描述的是**渲染行为**，projection 字段是遗留空壳；
2. 这些字段在**更早的 run**（本轮 15 个之外）曾非空，设计基于旧样本。

**无论哪种，结论对 F agent 相同**：去重**不能**依赖删除 projection 字段（它们本来就没内容），必须处理 `learning_summary` 与 `view.brief` 这对 96% 重叠的真实容器。

**未验证**：`DecisionBrief.tsx` / `ReaderSurface.tsx` / `WorkbenchLayout.tsx` 的实际挂载与派生逻辑。本 worktree 无 `frontend/node_modules`，且 F agent 拥有该文件所有权，A agent 不越界修改。**建议 F agent 在 T26 用组件测试断言「主摘要元素数量 = 1」时，一并确认这 3 个字段的真实来源。**
