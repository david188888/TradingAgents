## 目标与约束

报告让读者快速回答原问题；证据栏让读者核对事实；角色回顾让读者检查各环节的必要性和贡献。三者共同使用同一份经过资格校验的保存记录。提议、最终记录、执行检查和经济判断分别标来源及状态，未知数不填零。

## 实施顺序

1. **只读契约与资格**：runtime 覆盖标记；checkpoint/record 的可选序列上界；Web 过程和按角色产物 DTO、投影及 API。验证版本/身份/冻结 seed 摘要、产物 ID 和事实范围；不通过时明确降级。
2. **审计统计**：按 profile 选择实际角色；区分主预算授权、SDK 主/修复发出授权、数据能力与 HTTP；保留完整/下界/未知口径，同步 nullable 类型及全部消费点。
3. **桌面 Reader**：transport/hook 管理序列、SSE 刷新与跨运行隔离；问题优先报告、事实与原文证据栏、术语解释、过程和六角色产物回顾；保留估值/量化模块与完整记录入口。实体直达与上下文返回、抽屉焦点、桌面窄容器降级。
4. **验证与收尾**：离线测试覆盖读路径不写入、身份/哈希/版本拒绝、合法零与缺失、计数覆盖、响应乱序和产物直达；运行公共检查、相关 pytest/Vitest、构建静态资源与桌面 E2E。用已保存 002130 记录只读验证，更新当前运行文档并列出限制。

## 完成标准

- 当前问题、完整回答、重点依据、主疑点及核验建议可读且可追溯；所有非首页产物仍可达。
- 六角色及代码核查区分，原提议与最终处理分别可核对；旧/缺失/损坏数据不伪造归属。
- 运行过程持续更新且同一序列读取；终态收敛、跨运行与角色切换不会接受慢旧响应。
- 审计不再显示错误的 classic 角色或把未知 SDK/Token/时长写成 0。
- 不新增数据或模型请求；构建产物与源代码同步；桌面浏览器核对真实保存内容。研究质量不能因 UI 改版升格。
