## History and maintenance

[Archive](archive/README.md) retains historical plans, designs and verification records at their existing
paths. They describe their writing-time state, not current behavior or new authorization. Some older
current-document URLs now point to their maintained owner instead of repeating the same explanation.

Mark maintained explanations `Status: Current`. Historical material should identify its date/status,
link the current owner and state: **Do not use this document as evidence of current implementation behavior.**
Use the existing archive status labels, including verification/release records, consistently; do not
silently reinterpret old statements as today's test results. New routine changes need no separate
process narrative. Preserve only decisions or evidence that a future maintainer needs.
