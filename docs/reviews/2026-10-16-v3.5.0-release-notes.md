# TradingAgents v3.5.0 — 白话解读与可独立阅读的阶段产出

Status: Release notes

Python 包、frontend package 与 lockfile 根版本统一为 3.5.0。
沿用 GitHub Release 与源码归档渠道，不发布到 PyPI。

## 白话解读层

- Reader 在专业研究旁新增白话解读：指标定义、数字格式与针对已保存专业分析的
  模型解释，不修改基线记录/摘要、数值凭证、评级、研究质量或原始 Markdown。
- 主报告与证据栏/抽屉共用同一份解读；不支持的历史格式保留专业原文，不猜测含义。
- 新 Web 原生研究带 `report_explanation_policy=plain-language-report-v1` 创建标记，
  仅对 `research_profile == "evidence_v1"` 写入。发布并完成后由 manager 以冻结的
  快速模型参数调度有界任务；该调度为尽力而为，失败被抑制且永不改变运行终态。
- 历史运行在读取、恢复或启动时都不会获得该标记，只得到受支持的指标定义与数字格式。
- `GET /reader/explanations` 只读已校验的公开基线、确定性展示与已保存补充，
  不调用模型、不取数、不写入。`POST` 显式生成或重试，仅接受已完成的新研究，
  返回 `202` 或安全的 `409`；历史生成被拒绝，打开 Reader 与选择证据永不触发 POST。
- 补充层拥有独立 schema、提示、尝试日志与 `aux.report_explanation` effort 任务，
  与原生执行共享 `execution/model_request.py` 传输层，不引入模型/供应商回退。
  原始研究阶段计数不含此阅读辅助。

## 可独立阅读的阶段产出

- 新增 `stage_available` 可用性与 `stage_record` 字段：运行进行中即可读取已保存、
  独立资格认定的证据与各研究阶段产出。
- schema 强制 `stage_available` 必须携带同一 run 且**无 assessment** 的记录且无
  relations——阶段材料永远不是最终报告；其他可用性一律排除 `stage_record`。
- 阶段提案在发布前明确为暂定；打开视图永不回填研究。

## 契约与文档修复

- 补齐后端 `explanation_unavailable`（409）到前端 `ApiErrorCode`，修复线契约测试失败。
- 抽取 `execution/model_request.py` 共享模型请求传输（生命周期钩子注入、无研究日志），
  原生执行改用该传输并保持调度时序、全局信号量、用量记账与错误分类语义。
- 契约索引补齐 stage 投影、白话解读、V7 统一研究、估值链与 ATR 统计五行，
  并把白话兼容规则并入表格，消除重复叙述。
- 新建 `docs/archive/README.md` 作为完整归档清单（101 个历史文件），此前
  `docs/README.md` 仅列 59 条、遗漏 42 个；`docs/README.md` 由 177 行收回至
  82 行，只描述当前受支持行为。
- 删除 `ARCHITECTURE.md` 中已不存在的 "market views" 投影描述；README 文档入口
  由 v3.3.2 更新至 v3.4.0 发布说明。

## 验证与边界

发布前全量 Python 回归 3580 项、74 项子测试通过；20 条测试警告保留。384 项前端
单元测试，以及 typecheck/build、Ruff、141 页文档与差异检查通过。静态资产已重建。

白话解读与阶段产出阅读均已通过离线/浏览器路径验证；真实模型输出质量与预测
准确率未在本次发布中重新验证。自动解读任务的调度失败不改变运行终态，故运行
可正常完成而解读缺失，此时需显式重试。

GitHub 当前无 Actions workflow；没有配置检查不等于 CI 通过。发布不涉及自动生产
部署、其他项目、历史报告改写、分支清理或 Hindsight 操作。
