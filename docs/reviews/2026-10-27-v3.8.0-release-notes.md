# TradingAgents v3.8.0 — 当前资料、证据卡引用与逐条审查

Status: Release notes

Python 包、前端 package 和 lockfile 根版本统一为 3.8.0。
通过 GitHub Release 与源码归档分发，不上传 PyPI 或额外二进制安装包。

## 用户可见变化

- 新建单公司与批量研究不再要求选择日期，省略日期时由服务端采用上海当日。
  显式历史 API 请求及历史任务恢复保留原日期，不把今天的数据伪装成历史时点数据。
- 新研究使用带来源、位置与适用限制的 Markdown 证据卡，模型选择简短引用，程序生成原始观察、
  事实引用与绑定位置。已有字段上的多余前提绑定可丢弃；错误路径、越界、非法前缀与无效数字仍拒绝。
- 挑战环节要求每条已接受假设保留来源绑定的审查记录。没有新增挑战时也需解释审查依据，
  Reader 分别展示原假设与审查意见；“暂未发现额外反证”不等于没有风险。
- 新策略为各基础阶段保留一次结构修正机会，总上限为八次修正、20 次基础模型与 29 次总模型尝试；
  原始搜索配额与 900 秒研究时限不变，未标记历史任务维持旧协议、提示词与预算。
- 通俗解读改为分批处理并保存进度，每批最多 16 段和 32000 序列化字符，累计最多 24 次请求、
  五分钟原始截止。只补缺项，已接受项保留，未知派发不重发；未覆盖处明确保留专业原文。

## 正确性与兼容

修复了 deadline 被误报为用户取消、长证据发布的异常边界、局部坏引用使有效兄弟丢失，
以及解读响应已收到但接受结果未落盘时可能重复派发的问题。合成浏览器测试同步移除旧日期控件交互，
改为验证控件不存在、创建请求不传日期；历史 Reader fixture 保留原有保存语义。

Reader 固定检查中不同运营指标共用语义键时，显示值曾被最后一项覆盖。本版按检查与保存观察项
位置使用唯一显示地址，修正展示；原始记录、数值凭证和历史解读目标均不改写。

  这些检查存在重复，不相加，也不声称运行了全仓库测试。

  已更新的 Playwright 测试成功收集 36 项；没有把收集结果记作 36 项浏览器通过。
  另通过真实浏览器验证合成财务流程的创建、发布和历史读取。

  发布包从干净源码快照构建，核对新模块、前端静态资源及私有资料排除情况。

## 保留边界与风险

真实第二轮通俗解读只完成 **69/208 段**，五分钟截止后其余 139 段保留专业原文；本版未实现
在现有限额内保证全覆盖。最后一项从假设关联论断取检索用词的小修有离线回归，未为此另开真实模型运行。
模型仍可能生成非法 JSON 或不充分的解释；代码不会猜测修正 JSON、放宽来源或数值校验。
引用、算术和软件质量门槛通过，不能证明任意散文解释、经济因果、预测或研究结论正确。

`npm audit --omit=dev` 为 **0 条**；完整开发链审计仍有 **18 条既有告警：4 moderate、12 high、2 critical**。
依赖树未改变，仅同步根版本；开发工具链升级作为独立事项。Vite 仍提示约 601.75 kB 的主 chunk
超过 500 kB，未调高阈值或关闭检查。

GitHub Release 是源码发布，不代表已有本地服务已自动部署或重启。
本版不迁移历史运行记录，分支与验收现场保留，清场需要最终汇报后的单独确认。
