## 逐字段确认的触发条件

重新使用这次运行的 V0 和阶段缓存离线构造综合输入，SHA-256 与检查点一致。
把原始最终文本的引用别名还原后，能够重放同类拒绝。

1. 主响应的 `dimensions.2` 为经营项，引用了不属于该维度的事实。
   该判断文本没有数值令牌。数值编译器先调用 `_field_scope`，把维度引用越界报为
   `numeric_anchor_scope`，于是修复提示只强调数值令牌，未准确指出引用列表。
   估值项通过这一引用检查，不能把它列为本次已确认错误。
2. 主响应和修复响应都没有 `adjudications`，尽管已有 1 条挑战与专项回应。
   `SynthesisProposalV3` 的 canonical 默认值允许字段缺席，prompt schema 也将它显示
   为可省略；公开记录校验最终才要求每条挑战都有独立裁决。
3. 主响应先在经营引用处停止，遮蔽了同时存在的裁决缺失。修复回应修正了引用，
   随后在 `adjudication_coverage` 失败。这不是可以靠改写失败文案解决的问题。

## 本轮修复

- Canonical `validate_synthesis_reference_surface` 在数值渲染之前检查维度引用范围、
  裁决覆盖和局部挑战评估覆盖，聚合独立分段的问题；不补造裁决或修复事实引用。
- 新建 scoped 综合请求冻结 `native.reference_schema.synthesis=2`；prompt schema
  要求完整的两种挑战数组、准确的条数和维度数，并枚举已保存挑战 ID。
- 同一次既有修复机会收到所有已发现的引用分段问题、各维度可用 ID 与保存的回应绑定，
  明确 `challenge_assessments` 不替代 `adjudications`。
- 保留引用、数值、撤回/修正、发布校验与尝试上限。旧 schema-1 提示和读取路径不变。
- 采集开关默认关闭，仅保存综合失败的最终文本；过滤内部推理块和响应元数据，
  文件权限 0600，运行子目录 0700，采集失败不改变研究结果。

原始主响应经新 preflight 检出 `dimensions.2.claim_ids` 越界和 `adjudications` 缺失；
原始修复响应经新 preflight 检出 `adjudications` 缺失。两份仍然被拒绝，
没有被人为补成有效报告。入库测试只保留上述结构，全部公司文字、事实和 ID 已换成
合成样例；另用离线 SDK double 验证一次有限修复能同时纠正这两类结构错误。

## 下一步发布语义的待确认点

V8 §4.9 规定失败分段标为“未完成”、其余保留，但没有明确总体判断或关键挑战裁决
失败时，已经生成的总体评级是否仍能展示。这决定发布合同与 Reader 的含义。

建议：有效分段照常交付；总体判断或任一 `critical` 挑战的裁决分段经过有限修复仍失败时，整体暂不评级，
明确显示“综合未完成”，不会显示“财务证据不足”。其他分段的有效分析与来源保留。
这是执行/验证失败，不等同于证据稀疏；不能自动套用后续 Phase 5 的缺数据立场规则。
用户确认后再据此设计分段收据与发布状态，避免代码替模型补造裁决。
