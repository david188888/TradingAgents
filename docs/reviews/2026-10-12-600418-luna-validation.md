# 600418.SS diagnosis and subscription Luna validation

Status: dated investigation and local validation; not a research-quality claim.

## Original case

The case selected at the beginning of this investigation was
`run_20261012T063510642090Z_ed080e23` (2026-10-12 14:35–14:39 Asia/Shanghai).
The run completed and published a `partial / LOW_CONFIDENCE` research record,
but synthesis failed twice with `dimension_claim_reference`. The limited
assessment had no qualified supporting/opposing arguments or key claims.
Three specialists, three challenges and three targeted replies were saved.

The current valuation batch failed with
`valuation_quote_not_last_settled_session`: the returned quote date did not
match the last admitted settled session. The run started before 16:00, when
the current-day session is excluded from the data policy. Its admitted price
and historical-multiple cutoff was 2026-10-09. The failed quote itself was not
persisted, so its exact timestamp cannot be reconstructed from the checkpoint.
The record therefore omitted native valuation. Independently, the admitted
2025 annual attributable net income was negative; the native assembler does
not supply annual equity to the PB fallback. Correcting the snapshot alone
would not establish a reference value range.

## Why completed stages had no readable body during execution

The user confirmed that this occurred while the whole study was still running.
In the original case, operating research completed at event 194. Reading it
at event 257 returns `pending_publication / publication_pending` and no public
proposal. At final boundary 277 it returns `available` and one hypothesis.
This is the existing publication barrier, not lost specialist output. The UI
distinguishes execution and publication but the completed label can still be
misunderstood. This investigation does not change that barrier or expose model
reasoning.

## Local fixes

- V7 checks condition evidence/metric dependencies before saving a specialist
  proposal, using the same rule as the kernel. Invalid bindings get the existing
  bounded repair opportunity; no source qualification is relaxed.
- Kernel condition-binding errors use a typed evidence error, avoiding the
  blanket ValueError-to-missing-configuration classification.
- New V7 reference repair prompts include safe, fixed binding feedback and,
  for dimension errors, the exact allowed claim IDs from the original input.
  Existing generic repair hashes and unknown-dispatch non-replay are preserved.
- Fresh V7 specialist/synthesis prompts repeat the existing binding and structure
  rules, with a persisted stage marker. Already frozen prompts remain unchanged.
- Following user approval, fresh V7 synthesis uses deterministic short aliases
  for saved reference definitions. Exact reference fields are decoded before
  the unchanged evidence gates; prose, falsifiers and closed checks are preserved.
  Canonical proposals, not alias proposals, enter the cache. Old canonical and
  initial alias-format prompts retain their hashes during recovery.
- Argument-to-reply fact bindings are repeated explicitly, including maintained
  replies. One allowlisted public validator error can supply exact saved reply
  bindings to bounded repair, without raw response text or arbitrary messages.
- The outer record schema, historical prompts, model selection, repair ceilings,
  source collection and publication barrier remain unchanged.

These four complete-run tests consumed 26 SDK requests. None produced a valid
synthesis. They must not be labelled successful company research.

A separate two-request synthesis diagnostic reused the fourth run's frozen
record, without source calls or edits to existing runs. Main failed a root
assessment validator; repair used an unknown claim ID for operating quality
and an operating inference in the event dimension. Only reference categories
were observed, not reasoning or raw response text.

The user then approved prompt-local short reference aliases. The first isolated
alias test used two SDK requests: dimension references passed, but both main and
repair failed the existing argument-to-reply fact gate. The prompt was clarified
to state that rule for every cited reply, not just revised replies, and a fixed
allowlisted repair diagnostic was added. A second isolated test used two more
SDK requests: main failed the exact public falsifier-text gate; its one bounded
repair returned a valid synthesis and passed the existing public-record gates.
It supplied four dimensions, one supporting argument, one opposing argument,
two adjudications and three exact change conditions. The host still requires
`insufficient_evidence` because valuation support is missing.

This closes the frozen-evidence synthesis validation, not full company research
or valuation recovery. The four original full runs remain unchanged and no new
report was published into their Readers. The validation-only canonical proposal
is available in the task artifact `600418-luna-synthesis-validation.json`.
Free-text limitations in that proposal contain two short challenge labels;
these were not rewritten by the reference-field mapper. Structured references
are canonical and validated; prose quality remains a separate assessment.
The investigation has made 32 real SDK requests in total: 26 in full runs,
two in the earlier diagnostic and four in the approved alias validation.

The third run additionally exposed a Reader diagnostic gap: `budget_refused`
in the latest repair diagnostic masks the preceding reference failure, and
the process projection currently has no public explanation for that category.
That projection behavior has not been changed in this patch.

unified research, Reader projection and production wiring. The final combined

cross-dimension rejection, reply fact rejection and bounded repair, canonical
cache recovery, old prompt preservation and diagnostic secret exclusion.

changed. The idle local service was restarted to load the fixes.
