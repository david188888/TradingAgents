## 已交付行为

- 报告首先回答研究问题，再显示关键依据、最大疑点与下一步、实际检查、估值和量化背景；分级标题、区域与行宽使正文易于扫描。
- 证据栏按当前段落跟随或手动固定，展示绑定事实、保存原文或明确标识的来源字段、日期及适用范围；窄桌面容器使用带焦点边界的抽屉。金融概念使用固定解释，不临时生成公司判断。
- 导航提供证据目录、研究过程、Agent 产物和完整记录。贡献链接直达对应假设/挑战，显示原提议与最终处理，支持返回原阅读位置。所有合格的专项假设、条件、替代解释、专项未知项、挑战与完整综合提议可达。
- 六个真实角色与代码检查分开。主要疑点来自独立挑战，综合提议或代码关键级别规则选择；完整下一步保留综合原文。建议检查与实际执行分别展示。
- 新只读过程/角色 API 使用同一事件序列边界，验证版本、身份、seed 摘要、发布内容、ID 和历史专项资格。V1–V5 的读规则冻结，未来来源准入不会改变旧记录归属。旧缺失/不支持/损坏/未发布产物明确降级。缺乏合格输入而未调用、返回合法零提议与提议缺失分别显示。
- 技术诊断使用实际 native 角色，区分主/修复预算、SDK 主/修复授权、数据能力、HTTP、产物与 checkpoint 数量。缺失值不显示为零；旧 SDK 覆盖显示已知下界或未记录。新覆盖标记在 SDK adapter 的 MAIN 授权前保存，不改变研究/恢复身份。

相关 pytest 628 项通过，最后读投影/SDK 的 48 项关键用例定向通过（含新增的“空挑战与已发布非空挑战不一致”拒绝用例）；全量 Vitest 323 项通过。最终构建的桌面 Playwright 18 项全部通过。覆盖 1440/1280 桌面、问题优先报告、证据抽屉、Agent 切换、返回焦点、真实选择状态、窄桌面无横向溢出、技术诊断、取消以及 axe 检查。按用户要求排除手机尺寸。浏览器测试使用隔离临时存储和合成模型提议，不访问真实供应商。

`npm ci`、typecheck/build、全包 Ruff、文档链接检查（94 个 Markdown）及 `git diff --check` 通过；生成 SPA 与源代码同步。构建仍有大 chunk 提示，pytest 有现有 FastAPI 测试客户端弃用提示，均未构成功能测试失败。

本地 `127.0.0.1:8000` 在确认无活动研究后用原项目环境重载。新 API 的 9 条作者归属、6 个实际 Audit 角色及角色正文可读取；原 configured-key 布尔状态保持一致。目标运行全部 243 个保存文件的内容摘要在重载/读取前后相同。

本次没有修复 PDF 解析依赖、补取证据或重新运行研究，也没有评估预测准确率。新 UI 提高可读性和可追溯性，不增加原研究的证据强度。当前架构和操作入口见 [Reader 架构](../architecture/research-reader.md)与[研究操作](../operations/evidence-research.md)。
